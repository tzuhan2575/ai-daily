🚢 工具

Claude Code 的 /ship：一行指令把改動開成 PR、自我 code review、接著持續盯著 CI 與留言自動推修正；官方把『不能自己 merge』寫成硬限制

Claude Code 官方文件〈Get a pull request ready with /ship and /steward〉與〈Claude Ship〉（兩篇全文文字都讀了；流程圖是 SVG 圖片，沒看）＋Claude Code changelog v2.1.330（11/20）、v2.1.331（11/23）＋Latent Space AINews 11/24 的社群整理・11/23–11/24

Claude Code 新增 `/ship` 與 `/steward` 兩個指令（文件標示需要 v2.1.330 以上，v2.1.331 修掉多項限制；11/24 的 Latent Space 把它列為當日高互動話題之一，稱為 beta）。`/ship` 的流程是四步：① 幫你 commit、push 並用你的身分開 GitHub PR；② 用 `/code-review` 審自己這份改動；③ 進入「watch」——在你的 session 裡持續檢查這個 PR，處理失敗的 CI、合併衝突、審查留言與自己審出的問題，並把修正 push 上去；④ 由你自己按 merge。`/steward` 則跳過前兩步，直接對已開的 PR 開始 watch。官方列的限制相當具體：當 Claude 不是在回你的訊息時，Claude Code 會擋掉會 merge、approve、開啟 auto-merge 或 force-push 的 `gh`／`git` 指令，並把可用指令縮到一張短清單，連 WebFetch、WebSearch 與 connector 都停掉（可用 `/ship terms` 查看）。watch 最多跑 7 天，`Esc` 按一下就可能結束它。另外有一組給組織用、計費在組織額度上的 Claude Ship agent（Code Review 已 GA，PR Steward 與 Claude Approvals 公開 beta，Team／Enterprise 方案，ZDR 或 HIPAA 設定的組織不能用）。

白話：白話：以前你得自己開 PR、等 CI 跑完、看紅燈、回審查意見、再推一版。`/ship` 是把這一整段交給在你電腦上的 Claude：它用你的 git 與 gh 登入身分做事，所以 GitHub 上看起來就是你在推。關鍵設計是「可以一直修，但不能自己合併」——真正把程式碼合進主線的那一下，留給人。
💡 為什麼重要你就是用 Claude Code 在維護這個日報 repo 與 Tap Diary 的人，這是少數會直接改變你每天動作的功能。更重要的是官方文件把「agent 可以做什麼、不可以做什麼、哪些設定會讓限制失效」列得很細，正好是第 5 週『Agent 安全與權限』那四課的真實教材。
🎯 對你的影響　🔧 可立即用
你每天都在用 Claude Code 推這個 repo，而且你的日報流程是直接 commit 到 main、不開 PR；`/ship` 對日報用不上，但對 Tap Diary 這種你會想留審查紀錄的專案可能有用（推測）。要特別注意兩件事：這個日報 repo 是公開 repo，`/ship` 不會幫你 commit 未提交的檔案；而且你若在 watch 期間插話，安全限制會暫時關閉。
▶ 先別急著在主要專案上跑。在一個練習用的私人 repo 開一個小 PR，用 `/steward` 起 watch，然後立刻打 `/ship terms` 把官方列出的「可做／禁止」清單讀一遍並存進你的第二大腦；確認你的 settings 裡沒有 `Bash(git *)` 這類 ask 規則（它會讓 watch 卡在每個提示）。

我讀到什麼

讀了官方兩篇文件的全文文字（`/ship` 與 `/steward` 的操作頁、Claude Ship 的組織版總覽），以及 changelog v2.1.330、v2.1.331 的條目。流程圖是 SVG 圖片，我沒看到內容。要注意：changelog 裡我搜不到 `/ship` 這個指令的條目（只有 Code Review 相關），所以它的上線時間我只能依文件寫的版本需求推斷；Latent Space 稱它為 beta，這是電子報說法。我也沒有實際跑過（雲端 session 依文件就沒有這兩個指令）。

watch 期間 Claude 會自己做哪些事

在 auto 權限模式、GitHub PR 上，官方列出它不詢問就會做的事：處理它判定為問題的 review 發現、可以貼一則總結留言、push commit 到你的分支、把 base 分支合進你的分支（解衝突或跟上進度）、處理失敗的檢查並重跑、回覆 review 留言、resolve 討論串、重新 request review。它讀誰的留言也有界線：你的、有 write 權限的人的，以及 github.com 上 Claude 自己的 bot；要讀別的 bot 得用 `/steward +bot名稱`。

官方自己標出來的風險

文件有兩個明確的警告框，值得照抄進你的筆記：① 只在你信任「所有能 merge 到 base 分支、或能 push 到你分支的人」時才讓 watch 自己跑，因為他們都能用你的憑證在你電腦上執行程式；② watch 的限制不是萬能的——它用你的 gh／git 登入，所以在分支規則允許你一個人 merge 的 repo，它本來就有能力 merge。文件還列出程式碼會從哪些來源跑進你電腦：base 分支（含會自動執行的腳本）、別人 push 到你分支的東西、你自己的測試、你的 Claude Code hooks，以及 repo 裡的 `.claude/skills/steward/SKILL.md`（任何能 merge 的人都能寫這個檔）。

限制在什麼時候會失效

這是最值得記的一段：在終端機 session 裡，當 Claude 閒置、你打了一句話，上面那些限制在它回答你的期間是關掉的；此時在 auto 模式下它有可能被允許 merge。另外若 PR 開了 auto-merge，Claude 推的修正本身就可能觸發合併（官方給的關法是 `gh pr merge --disable-auto <編號>`）。權限規則也有反直覺之處：watch 期間 Claude 的 git 指令寫成 `git -c core.hooksPath=/dev/null push` 這種形式，所以 `Bash(git push *)` 這類 ask 規則比對不到、不會跳確認，而 `Bash(git *)` 比對得到、會讓 watch 在每個提示停住（連 auto 模式也是）；deny 規則則會讓 watch 根本不啟動。

組織版的三個 agent

Claude Ship 把同一套拆成三個角色：Code Review（在行上留 inline 留言、依嚴重度排序）、PR Steward（處理失敗檢查、衝突與留言並推修正，設計上不 approve 也不 merge）、Claude Approvals（依你寫的 `.claude/approvals.yml` 政策回報還需要誰核准，只有把它設成 GitHub 必要檢查才真的擋 merge）。官方自己提醒：如果政策不要求人核准、又開了 auto-merge 或 merge queue，改動可能在沒有任何人動作下就合併。另外有個計費陷阱寫得很清楚——關掉 usage credits 不會讓 agent 停，它會繼續跑並繼續計費，要停得照順序關掉 agent。

觀察點

① `/ship` 何時從 beta 變正式、changelog 會不會補上條目；② 公開 repo 的行為差異（文件說公開 repo 不會幫你 commit 未提交的檔案，這對你這個公開日報 repo 直接相關）；③ 它找 secret 的方式只看檔名（例如 `.env`），自己看過檔案仍是必要的；④ 七天上限與 `Esc` 誤觸結束 watch 的實際體感。

🧬 研究

OpenAI 說 GPT-6 不靠專用生物模型、只用推理和寫程式就能設計蛋白質：實驗室做出 322 個小蛋白、35 個（10.9%）驗到結合；但從序列預測完整結構仍大幅落後專用模型（0.38 對 0.93）

OpenAI 官方文章〈GPT-6 models demonstrate intrinsic protein-design capabilities〉（已讀全文文字；所有蛋白質結構圖、雷達圖都是圖片，沒看；預印本〈GPT-6 as a Universal Foundation Model for Protein Biology〉沒讀）・11/24

OpenAI 11/24 發表與生技公司 Onava 合作的研究：GPT-6 系列在不呼叫 RFdiffusion、ProteinMPNN 這類專用蛋白質模型的情況下，單靠推理與寫、執行程式碼來設計蛋白質的三維結構與胺基酸序列。實驗室結果有三組：① 給五個標的蛋白與「要黏在哪裡」，GPT-6.2 設計小型結合蛋白（minibinder）的立體結構，再由專用模型 SolubleMPNN 補序列、其他專用模型篩選候選，共做 322 個、35 個（10.9%）驗到與預期標的結合（PD-L1 5 個、IL-7Rα 3、TrkA 1、VEGF-A 8、IL-17A 18）；官方說原始 RFdiffusion 論文回報的命中率更高，但命中率高度取決於送驗前篩得多嚴、以及怎麼定義「結合」。② 反過來只給結構、要它補序列：MDM2 88 個中 75 個（85%）、VEGF-A 42 中 26（62%）、PD-1 59 中 8（14%）驗到結合，且產出序列和原序列中位差異達 50%／43%／15%。③ 抗體的辨識環（CDR）重設計：182 個設計中 128 個（70%）仍結合 IL-4Rα；對五種治療用抗體做「改掉約一半胺基酸」的 272 個片段中 179 個（66%）仍結合原標的。純電腦評測方面：motif scaffolding 在 MotifBench 30 題上，最新內部模型 43.7% 對 RFdiffusion 27.8%；小分子 docking（PoseBusters）GPT-6.2 93%、內部模型 96%、專用的 DiffDock-L 50%。弱項官方講得很直白：從序列預測完整結構的 TM-score，GPT-5.6 0.16、GPT-6.2 0.26、最新內部模型 0.38，而專用的 ESMFold2 是 0.93。

白話：白話：蛋白質是胺基酸串成的鏈，摺成特定立體形狀才有功能。過去要設計新蛋白，得用一堆專門的 AI 模型（一個生形狀、一個配序列、一個預測摺法），每個吃的輸入格式都不一樣，要串起來得有專業知識。這篇的主張是：通用大模型可以用「想一想＋自己寫程式算」的方式直接做其中幾段，而且你能用自然語言指定條件（黏在哪個位置、要幾段螺旋）。但它還不能取代整條流程——篩選候選、預測摺法還是靠專用模型。
💡 為什麼重要跟你的日常開發沒有直接關係，但有一個對所有工程師都重要的觀察：模型把「叫外部工具」換成「自己寫程式算」之後，在某些結構化任務上追上甚至超過專用模型，同一支模型還能靠改 prompt 切換任務。這是「通用模型吃掉垂直模型」這條趨勢最具體的證據之一，也附帶一個反例（完整結構預測差了一大截）。
🎯 對你的影響　💤 略知即可
你不做生物相關開發，這則對你是趨勢觀察而非可用工具。唯一可帶走的是「鋸齒狀能力邊界」這個判斷習慣：同一模型在相鄰任務上的表現可能差好幾倍，不能靠一兩個分數外推。

我讀到什麼

讀了官方文章全文文字，含所有數字。文中的蛋白質結構示意圖、能力雷達圖都是圖片，我沒看到內容；預印本與論文也沒讀。所有數字都是 OpenAI 與合作方 Onava 自己測的，沒有第三方重現。

官方自己列的保留

這篇的自我限縮寫得比多數廠商文章清楚，值得照單記下：① 整個設計流程仍依賴 Boltz-2、OpenDDE、ESMFold2 等專用結構預測模型做候選篩選，所以「結果不足以證明模型能端到端、零樣本地從頭生出 minibinder」；② 在「從結構反推序列」這類測試中，異常高的準確率可能部分來自記憶，或來自產生那些結構的流程留下的痕跡；③ 結合（binding）只是第一步，專一性、穩定性、生物活性與安全有效性都還沒驗；④ 抗體 docking 那組測試用的是公開結構，模型訓練時可能看過。

為什麼說不只是背答案

官方舉的證據是：針對一個「未發表」的 PD-L1 minibinder 結構，GPT-6.2 生出兩條各與原序列差 52 和 58 個（全長 90 個胺基酸）、彼此也差 44 個位置的序列，兩條在實驗室都看到結合跡象。這是我讀到的文字敘述，沒有原始資料可核。

jagged frontier（鋸齒狀能力邊界）

這個詞在 OpenAI 近期文章反覆出現（11/18 也有一篇同主題）。這篇是很乾淨的例子：同一個模型在 docking（93% 對專用模型 50%）大勝，在「只給序列預測整個結構」卻遠輸（0.38 對 0.93）。對你評估任何模型都適用——能力不是一條線，是一塊缺口很多的鋸齒，必須逐任務測（第 3 週『評測與選型』與你自己那支 eval 的用意）。

生物安全

文章末段說同樣能力也可能被濫用，風險評估走他們的 Preparedness Framework，但沒有公布這次的評估結果或任何具體管控措施。另外要注意這類研究的連鎖效應：當通用模型本身就具備設計結合蛋白的能力，原本靠「限制專用生物模型存取」的管控路線就會失效，這點文章沒有討論。

沒有回答的問題

一次設計要花多少推理成本、用了多少運算（文章完全沒提）、「最新內部模型」是什麼、一般開發者能不能透過 API 做這些事、實驗室驗證的詳細條件（結合強度門檻、對照組）都不清楚。我也沒看到任何第三方生物學家的評論。

🚩 產業觀點

一家公司在 HN 求救：被 Anthropic 指控拿 API 做蒸餾、限 24 小時內自證清白；發文者說自己唯一可疑的用法是「每次改 AI 設定就跑一輪自動回歸測試」

Hacker News〈Ask HN: Anthropic is accusing my company of distilling. How can I prove I'm not?〉（原貼全文與前 14 則頂層留言都讀了；發文者說法無法查證，Anthropic 未回應此事，我也沒找到官方說明）・11/24

11/24 一則 Ask HN（207 分、161 則留言）：發文者說自己公司被 Anthropic 指控用其 API 進行蒸餾（distillation），但公司並不訓練自己的模型，唯一想得到可能被標記的行為，是每次更動 AI 設定時跑的自動回歸基準測試；他認為這不違反政策，卻被要求 24 小時內證明清白，並問「在不破壞使用者隱私的前提下，要怎麼證明自己沒有蒸餾」。熱門回覆大致分幾類：拿出測試框架的原始碼與 git 歷史當「用了多久」的證據（最高票）；先確認 API 金鑰沒有外洩、被別人拿去跑蒸餾；把要送出的證據先丟給 Claude 問夠不夠有力，因為審查的另一端很可能也是 Claude；找律師而不是找 HN；以及大量「換一家供應商」「無法證明否定命題」「訓練資料本身就來自全人類知識，指控很諷刺」這類情緒性回應。

白話：白話：蒸餾是指拿一個強模型的大量輸出當教材，訓練自己的小模型——幾乎所有前沿模型供應商的使用條款都禁止。問題在於：從供應商的後台看，「有系統地大量發問、收集回答」這件事，和「跑自動化回歸測試」「大量批次處理」在流量特徵上長得很像。於是正當用法也可能被判定成蒸餾，而你很難證明自己沒做某件事。
💡 為什麼重要你自己就在 Claude Code 之外跑自動化的事（這個日報 routine 每天自動產出、你也寫過自己的 eval），這類自動化流量正是容易被誤判的樣子。這則提醒的是一個很實際的工程風險：單一供應商帳號被停＝你的自動化整條停擺，而申訴窗口可能只有 24 小時。
🎯 對你的影響　👀 值得追蹤
你的日報 routine 每天自動呼叫模型、你也寫過自己的 eval，這類流量理論上可能被誤判；但你的量很小（每天一期），被標記的機會應該很低（推測）。真正要防的是「單一帳號被停＝自動化全停」。
▶ 花十分鐘做一份「自動化用量說明」存進第二大腦：每天幾次呼叫、什麼觸發、輸出存不存、存多久，並記下這個 repo 的 git 歷史就是你的證據；順手確認日報與 Tap Diary 沒有共用同一把金鑰。

上層導航策略在 50 Hz 輸出的不是關節角度，而是速度指令（前進、橫移、偏航），由凍結的走路策略去執行。訓練時 actor 只拿得到真機上也有的資訊（ToF 歷史、機身與控制器狀態），critic 則額外吃模擬裡的狀態來幫助學習、部署時不需要——這是強化學習裡常見的 asymmetric actor-critic 設計，官方沒有用這個名詞，但描述就是這件事。

sim2real 靠什麼撐

ToF 的模擬刻意做髒：隨機化安裝俯仰角 ±10°、安裝高度 ±2 公分、地板判定的中點偏移 0–13 公分、格子邊緣有 50% 機率失效，另外加上雜訊、延遲與遺失讀值，而且官方說感測器位置與地板讀值是參考真機錄下來的資料校準的。這就是 sim2real 的核心手法：與其把模擬做得更真，不如把模擬做得夠亂，逼策略不依賴任何一種乾淨訊號。

值得抄的一句是「依指令前進只有在『有足夠餘裕』時才拿得到分數，冒險逼近會減分」。這等於把安全距離寫進獎勵，而不是事後靠一個硬性的煞車規則補。真機端仍另外加了兩道保險：近距離煞車、輸入過期就停，速度上限 0.15 m/s。多層保險的思路和第 5 週那幾課談的權限閘門一模一樣。

📘 今日一課 · 12 分鐘

VLA 之前先搞懂機器人策略的輸入輸出：分層控制、動作空間與 50 Hz 的時間預算

為什麼今天學這個

昨天（11/24）上了第 7 週『多模態與機器人模型』的第一個主題『VLM 的視覺編碼器』——模型怎麼把圖變成 token。今天 NVIDIA 的 Microduck 避障教學正好接上另一半：策略怎麼把感測器讀值變成動作，以及為什麼要把『走路』和『避障』拆成兩層。這一課是第 7 週第二個主題『VLA 與世界模型』的前置——VLA 的 A 就是 action，不先搞懂動作怎麼被表示、以什麼頻率送出，後面讀 VLA 論文會卡住。

是什麼：策略就是一個函式

機器人學界說的『策略』（policy）其實就是一個函式：吃觀測（observation）、吐動作（action）。它多半是個不大的神經網路——Microduck 的導航策略小到可以匯出成 ONNX、在筆電上跑。三件事決定它長什麼樣：① 觀測空間：有哪些數字進去（感測器讀值、機身狀態、操作者指令，通常還有最近幾個時刻的歷史）；② 動作空間：吐出來的數字代表什麼（關節角度？速度指令？末端位置？）；③ 控制頻率：每秒要吐幾次。

為什麼要分層：凍結下層只訓上層

Microduck 的例子是：下層『走路策略』（怎麼邁步不跌倒）訓練完權重整個凍結，上層『導航策略』只負責把操作者的速度指令改成避開障礙的速度指令，再餵給下層。好處有三：① 不會學新技能時把舊技能弄壞（災難性遺忘）；② 上層的動作空間只有 3 個數字（前進、橫移、轉向），比十幾個關節角度好學太多；③ 上下層可以跑在不同頻率與不同機器上——官方的實機部署就是導航策略在筆電、走路策略在機器人上。代價是上層只能透過下層能理解的指令去表達意圖，做不到需要特殊步態的動作。

動作空間：同樣叫動作，差很多

常見幾種，由低到高：關節力矩或關節角度（最直接、最難學、頻率要高，通常 100–1000 Hz）；身體速度指令（像 Microduck 的前進／橫移／偏航，50 Hz 這種量級）；末端執行器位姿（機械手臂常用）；再上去是離散的技能或語言指令（『拿起杯子』）。VLA（vision-language-action）模型多半輸出的是中高層的動作——末端位姿或位姿的小增量（delta），有些還把連續動作離散化成 token 來生成。你看任何機器人論文，先翻到『action space』那段，才知道它實際在控制什麼、能不能跟你的硬體接上。

時間預算：頻率決定你能放多大的模型

控制頻率直接換算成延遲預算：50 Hz 就是每 20 毫秒要吐一個動作，100 Hz 是 10 毫秒。這個數字決定你能放多大的網路——一個幾十萬參數的 MLP 在 CPU 上是微秒等級（下面的小實作會實際量給你看），但一個幾十億參數的 VLA 一次前向可能要幾十到幾百毫秒，根本放不進 20 毫秒。這就是為什麼大模型機器人方案幾乎都是分層的：大模型低頻（1–10 Hz）出高層動作或子目標，小策略高頻（50–1000 Hz）負責執行。這和第 3 週『延遲怎麼量』是同一套帳，只是這裡逾時的後果是機器人跌倒。

觀測裡的歷史與隨機化

兩個實務細節。① 歷史：單一時刻的感測器讀值往往不夠（看不出東西在靠近還是遠離），所以觀測通常把最近幾次讀值疊起來——這會讓觀測向量變大好幾倍，下面的小實作會算給你看。② 隨機化：Microduck 在模擬裡隨機化 ToF 的安裝俯仰角 ±10°、高度 ±2 公分、邊緣格子有 50% 機率失效，還加雜訊與延遲。用意是逼策略不要依賴任何一種乾淨訊號——你在 CV 做資料增強是同一件事，只是這裡增強的是感測器而不是影像。

怎麼接回 VLM

昨天那課講的是『圖 → 視覺 token』，今天講的是『觀測 → 動作』。VLA 就是把兩段接起來：視覺編碼器把畫面變 token、語言模型處理指令、最後接一個輸出動作的頭。下一課讀 VLA 時，你要看的三個欄位就是今天這三個——觀測裡有什麼、動作空間是什麼、跑多少 Hz。

範例檔案

"""做一個玩具導航策略（ONNX），檢查輸入輸出形狀，並量它跑一步要多久。"""
import time
import numpy as np, onnx, onnxruntime as ort
from onnx import helper, TensorProto

TOF_H = TOF_W = 8          # ToF 8x8 距離格
HIST = 4                   # 保留最近 4 次 ToF
STATE = 9                  # 機身狀態：角速度 3 + 重力方向 3 + 操作者指令 3
OBS = TOF_H * TOF_W * HIST + STATE
ACT = 3                    # 前進、橫移、轉向
HID = 256

def make_policy(path):
    w1 = np.random.randn(OBS, HID).astype(np.float32) * 0.05
    w2 = np.random.randn(HID, ACT).astype(np.float32) * 0.05
    nodes = [
        helper.make_node("MatMul", ["obs", "w1"], ["h"]),
        helper.make_node("Tanh", ["h"], ["ha"]),
        helper.make_node("MatMul", ["ha", "w2"], ["raw"]),
        helper.make_node("Tanh", ["raw"], ["action"]),
    ]
    g = helper.make_graph(
        nodes, "toy_nav_policy",
        [helper.make_tensor_value_info("obs", TensorProto.FLOAT, [1, OBS])],
        [helper.make_tensor_value_info("action", TensorProto.FLOAT, [1, ACT])],
        [helper.make_tensor("w1", TensorProto.FLOAT, [OBS, HID], w1.ravel()),
         helper.make_tensor("w2", TensorProto.FLOAT, [HID, ACT], w2.ravel())])
    m = helper.make_model(g, opset_imports=[helper.make_opsetid("", 18)])
    m.ir_version = 10
    onnx.checker.check_model(m)
    onnx.save(m, path)

make_policy("toy_policy.onnx")
s = ort.InferenceSession("toy_policy.onnx", providers=["CPUExecutionProvider"])
for i in s.get_inputs():  print("輸入", i.name, i.shape, i.type)
for o in s.get_outputs(): print("輸出", o.name, o.shape, o.type)
print(f"觀測向量 {OBS} 維 = ToF {TOF_H}x{TOF_W} x {HIST} 次({TOF_H*TOF_W*HIST}) + 機身狀態 {STATE}")

rng = np.random.default_rng(0)
obs = rng.normal(size=(1, OBS)).astype(np.float32)
s.run(None, {"obs": obs})                      # 暖機
t = time.perf_counter()
N = 500
for _ in range(N): a = s.run(None, {"obs": obs})[0]
ms = (time.perf_counter() - t) / N * 1000
budget = 1000 / 50
print(f"一步推論 {ms:.3f} ms；50 Hz 的預算是 {budget:.1f} ms，用掉 {ms/budget*100:.1f}%")
print("動作輸出", a.ravel().round(4), "（tanh 之後落在 -1~1，之後要乘上速度上限）")

📚 今日新名詞

蒸餾（distillation）拿一個強模型的大量輸出當教材，訓練自己的小模型；多數 API 使用條款禁止這樣用。
watch（/ship 的持續看顧）Claude Code 在你的 session 裡持續盯著某個 PR，處理失敗檢查、衝突與留言並推修正，最長七天。
auto-mergeGitHub 的設定：檢查與審查都通過時自動合併，所以 agent 推的修正也可能間接觸發合併。
minibinder（小型結合蛋白）刻意設計來黏住特定標的蛋白的小蛋白，常用於藥物與研究試劑。
motif scaffolding先固定幾個關鍵胺基酸的三維排列，再設計其餘部分把它們撐在正確位置上。
docking（對接）預測小分子會黏在蛋白質的哪個位置、以什麼方向嵌進去。
TM-score比較兩個蛋白質三維結構相似度的分數，1 為完全相同，超過 0.5 通常代表抓到整體摺法。
鋸齒狀能力邊界（jagged frontier）同一個模型在相鄰任務上的表現可能差好幾倍，能力不是一條平滑的線。
ToF 感測器（time-of-flight）用光往返時間量距離的感測器；本文那顆輸出 8×8 格、每秒 15 次的距離值。
分層控制（hierarchical control）上層決定要往哪走、下層負責怎麼動；常見做法是凍結訓好的下層，只訓練上層。
sim2real 與域隨機化在模擬裡刻意加入雜訊、延遲、安裝誤差與失效，逼策略不依賴乾淨訊號，才能搬到真機上。
ONNX跨框架的模型交換格式；訓練完匯出成 ONNX，就能用輕量的 runtime 在部署端載入推論。
