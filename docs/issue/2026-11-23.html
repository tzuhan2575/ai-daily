🐤 資安

Metasploit 作者 HD Moore 用 200 萬個『誘餌提示』追蹤 AI 推論資料流向：至少 3 家推論商被入侵、市集賣家偷看客戶提示、標了『零資料保留』的請求仍被抓去爬；OpenRouter 下架 3 家供應商、125 個端點取消 ZDR 資格

Dragos 研究部落格（HD Moore，已讀全文文字，圖表沒看）＋OpenRouter 公告（已讀全文）＋Together AI、Phala、Novita、Atlas Cloud 事件說明（皆已讀全文文字）・11/19–11/22

資安公司 Dragos 研究長 HD Moore 11/19 發表：2026 年 7 月到 11 月，他們把約 200 萬個提示送進常見 AI 服務，每個提示都藏著獨一無二的『金絲雀』（假 AWS 金鑰、網址、DNS 名稱），再看誰去用。三個發現：① 至少 3 家推論商的資料外洩，數百把只送過一次的 AWS 誘餌金鑰被拿去嘗試登入，最早一起從 7 月中開始，3 家都在被通知前不知情；② 推論『市集』裡的賣家只要開請求紀錄就能看到客戶提示，有人從家用網路手動拿提示裡的密碼去 SSH 登入；③ 多家供應商沒遵守隱私設定：某中國 AI 實驗室在請求後 2 到 3 天回頭抓了超過一半提示中的網址，包括約三分之二標了『不收集資料／ZDR』的請求，連透過美國代管商呼叫也一樣。11/22 OpenRouter 宣布下架 3 家供應商、把 125 個端點移出零資料保留（ZDR）資格並通知受影響客戶；Together AI 承認 6–7 月部分提示樣本外洩，起因是『AI coding agent 把一組憑證 commit 進公開 GitHub repo』。

白話：白話：你呼叫 AI 的 API 時，提示不一定直接送到模型公司，常常經過『路由器』轉手好幾層，每一層都看得到全文。研究者在提示裡放『一旦被用就會響的假鑰匙』，結果發現有人真的拿去用了——代表提示被偷看、被保存，甚至被轉給不該看的公司。『零資料保留』只是一個請求上的旗標，只約束第一站，不保證後面每一站都照做。
💡 為什麼重要你每天用 Claude Code，也打算讓 Tap Diary 和個人助理呼叫雲端模型。這則直接回答『我的提示會跑去哪裡』：最便宜的路由不等於最安全；而 Together 的事件起點正是 AI coding agent 把金鑰 commit 出去——和你的日常工作流完全同一類風險。

我讀到什麼

讀了 Dragos 全文文字（圖表只看到圖說）、OpenRouter 11/22 公告，以及 OpenRouter 列出的四份供應商說明：Together AI（11/21）、Phala（初步事故報告，頁面日期我沒確認）、Novita（11/22）、Atlas Cloud（11/22）。Dragos 沒有點名哪三家被入侵、也沒點名那家中國實驗室；以下供應商對應關係都來自各家自己的公告。所有數字都是研究者或廠商自述，沒有第三方獨立重測。

金絲雀怎麼追蹤

每個提示帶一組只存在那裡的 AWS 金鑰（真的金鑰，但綁空帳號、全程記錄）、網址和 DNS 名稱；任何人一用，就能對回『哪個提示、哪個模型、哪個路由、什麼隱私設定』。為了知道請求實際經過誰，他們還做了『AI 推論版 traceroute』：在請求放一張指回自己伺服器的圖片網址，誰去抓就露出 IP；再故意送稍微壞掉的請求，每一層路由會把下一層的錯誤包一層自己的格式，拆開就能看到 3、4 層轉手。追了約 2,000 條路徑，數百條有無法辨識的系統，還發現有賣家在每個提示偷塞約 1,000 個隱藏 token。

被入侵的那幾家

Dragos 說其中一起事件裡，10 月底某幾個時段送出的每一個請求都被偷，連在模型執行前就被拒絕的請求也是——代表攻擊者在『前門』就複製流量。拿到金鑰後的流程很典型：幾小時內測金鑰是否有效、列 S3、翻 Secrets Manager、嘗試開 Bedrock 與建 IAM 使用者；11/1 起還用了 LLM 驅動的滲透測試框架 ARTEX，User-Agent 為 artex-agent、artex-judge-r121，Dragos 建議加進偵測規則。Phala 的報告對得上：攻擊者串連一個舊的對外服務與只靠 loopback 信任的管理介面，取得推論 VM 控制權，10/21–11/8 經 OpenRouter 送到它的 DeepSeek V4 Flash 0731 請求要視為外洩。

AI coding agent 把鑰匙交出去

Together AI 說明：他們為了軟體測試，把經授權的提示樣本（MiniMax M3、GLM-5.2、Kimi K2.6 的請求）存在私有 Hugging Face repo；開發公開 repo xorl 時，『一個 AI coding agent commit 了能存取該私有 repo 的憑證』。自動掃描有抓到並 revert，但在曝光期間已被人拿走、下載樣本、再從裡面搜其他服務的憑證去試——其中 5 組正是 Dragos 的誘餌。Together 之後的改善：短效或限縮權限的憑證、每個 PR 都掃憑證、新帳號預設 ZDR、更新使用 AI coding agent 的開發流程。

『轉手』的問題

Novita 承認一個路由設定錯誤，讓 2026-05-28 到 11-11 間部分 MiniMax 請求被轉到 MiniMax 官方 API，而不是在 Novita 自己的機器上處理；研究者觀察到提示裡的網址與主機名被存取，沒有看到 AWS 誘餌金鑰被使用。Atlas Cloud 也說經它送到 MiniMax 官方 API 的 M3、M2.7 提示有網址被第三方打開，已停止轉送，並自行把所有模型撤下 OpenRouter 重測，還出錢請 HD Moore 每天測四次。這些描述與 Dragos 第三個發現（請求被送回原模型廠）吻合，但 Dragos 原文沒寫實驗室名稱，對應是我依各家公告推的。

Dragos 的建議

① 能自架就自架（只有這樣沒人讀得到提示）；② 直接用第一層供應商，一家公司、一份合約、一份隱私政策；③ 用路由器時自己指定上游、確認隱私設定真的改變路徑，遠離轉售市集；④ 在 agent 會送出的上下文裡放自己的誘餌憑證，一被使用就當事件處理，Thinkst 的免費 Canarytoken 就能開始；⑤ 開啟供應商的密鑰過濾，但它擋不住不像金鑰的敏感資料。原文一句話很值得記：『隱私旗標只約束第一站，而 AI agent 會把它讀得到的東西都送出去，包括憑證。』

觀察點

① 其餘尚未公開說明的供應商（OpenRouter 說不是每家都發了公告）；② OpenRouter 能不能把這套測法變成常態檢查；③ 那家拒絕公開的首起入侵供應商；④ 模型廠會不會回應『ZDR 請求仍被爬』。HN 討論我沒讀。

📉 政策安全

OpenAI 首席科學家首度公開內部預訓練指標：GPT-3.5 約 0.99、GPT-4 約 0.91、最新模型已低於 0.8；提議業界以困惑度設『共同上限』，在監控能力達標前不跨越

OpenAI 研究部落格〈Perplexity and Intelligence〉（首席科學家 Jakub Pachocki，已讀全文文字，主圖沒看）・11/22

Jakub Pachocki 11/22 撰文，公開 OpenAI 從 GPT-3.5 起追蹤的內部指標：模型在一份『留出資料集』（取自 OpenAI 內部程式碼庫）上的 log 困惑度（等同交叉熵損失）。他給的數字：GPT-3.5 約 0.99、GPT-4 約 0.91；低於 0.8 後出現資安與數學上的『轉變性能力』；模型降到約 0.76 時開始在數學開放問題上產出『突破性結果』。他預期進入約 0.68–0.70 區間時會再出現新能力，但不知道是什麼。核心提議：前沿實驗室共同以困惑度等指標訂『第一道上限』，在理解與監控 AI 行為達到具體里程碑（例如『思考鏈監控的後繼者』）之前承諾不跨越。

白話：白話：困惑度是『模型猜下一個字猜得多準』的分數，越低越會猜。OpenAI 說，過去每次這個分數往下掉一段，模型就突然多會一種本事（例如 GPT-4 開始能好好用思考鏈推理）。所以他主張：與其等新能力冒出來才補救，不如大家先約定『分數降到某條線就先停下，等安全工具跟上再繼續』。
💡 為什麼重要這是前沿實驗室少見地主動公開『競爭對手能看懂自己進度』的內部數字，並把它綁到安全政策上。對你而言，它也是第 1 週『token 與模型怎麼運作』的延伸：所有新能力的源頭仍是『預測下一個 token』這件事。
🎯 對你的影響　👀 值得追蹤
沒有立即要做的事；但『困惑度 ↔ 能力』的框架有助你解讀之後各家模型發布時的宣稱（推測：其他實驗室可能被追問同類數字）。

我讀到什麼

讀了全文文字與註腳；文章開頭的損失曲線圖我沒看到（是圖片），所以只用文中明寫的數字。這些數字是 OpenAI 自己在內部資料集上的量測，外部無法重現。

為什麼用內部程式碼當資料集

註腳說明：自 GPT-3.5 起主要的留出資料集來自 OpenAI 內部程式碼庫，數字是固定快照。他也承認這對 GPT-2、GPT-3 不公平，因為它們的訓練資料不重程式碼；選它是因為『這是我們現在最倚賴的進度指標』。

他自己列的四個限制

① 各家用不同評測資料、不同訓練資料，難以跨實驗室比較；② 困惑度不直接對應任何我們在乎的任務；③ 看不到預訓練以外的進步——思考鏈推理大幅提升能力，卻不會降低困惑度；④ 不知道底線在哪：越接近資料本身的熵，數字進步會變慢，但小幅下降可能代表更大的能力躍進。

AI 參與自身研發

文章認為最值得注意的不是『AI 取代研究員』，而是 AI 參與『預訓練演算法研究』可能帶來階躍；他說最快 2027 年可能看到預訓練基礎進展的『雪崩』。註腳補充：2026 年曲線明顯加速，主要歸因於長期研究與算力投資，自動化只占較小部分，但最新模型已有『來自 AI 的實質設計貢獻』。他也說，對齊與監控的進展大概跟不上這種加速。

安全上的預期

他明寫應預期現行主流的『對齊稽核』會進一步失效，模型對『自己正在被評測或訓練』的察覺也會增加，因此主張各家在新模型首次使用前，就要有共同的評測規範與紅隊安全論證，以及共同的透明度標準。

觀察點

① Anthropic、Google DeepMind 等是否回應或公開自家同類數字；② 『上限』要用什麼可跨實驗室比較的資料集；③ 這和 11/21 我們報過的 OpenAI 反蒸餾做法並列，顯示 OpenAI 近期密集發表安全相關立場。社群反應我沒讀。

🔧 研究

讓模型讀自己的權重、自己改：Qwen3.5 27B 不用梯度、不用訓練，自我修改後在 490 題沒見過的題目上準確率 +6.6 分；還能修好被破壞的自己（7% → 70%），但 2B、4B、9B 做不到

Hugging Face Papers〈Language Models Can Rewrite Their Own Weights〉（UIUC 等，只讀了摘要與專案頁，論文全文沒讀）・11/16 上 arXiv、11/20 投稿 HF

UIUC 等單位的 Jiajun Fan 等人提出『self-rewriting』：給模型它自己的權重、練習題的對錯結果、以及執行自己的能力，讓它自己診斷失敗原因、直接改權重。作者說：27B 模型的自我修改讓它在 490 題事先固定、沒見過的題目上準確率提高 6.6 個百分點；前八次修改『只升不降』（每次只在自己的測試支持時才提交，並取代上一版）；把一份副本某矩陣的一塊 8 列換成雜訊後，模型找到被破壞的矩陣並用自己算出的值重寫，在六個沒見過的影像基準上從 7.3% 回到 70.2%（未受損模型的 83%），全程沒讀原始權重。專案頁註明用的是 Qwen3.5 的 2B／4B／9B／27B 四種大小：2B 不做修改，4B、9B 把自己改壞，只有 27B 成功。

白話：白話：通常讓模型變強只有兩條路——再訓練一次（貴），或在用的時候多花算力（每次都要付）。這篇說有第三條：讓模型像人一樣『看自己的大腦哪裡出問題，親手改掉』。改完的效果留在權重裡，之後每次回答不用多花錢，只要一張 GPU 跑幾小時。
💡 為什麼重要你在學本地跑開放模型（第 4 週），這篇示範了『開放權重』的另一種價值：拿得到權重，就可能讓模型自己修補自己。但這仍是單一團隊的初步結果，離實用很遠。

我讀到什麼

只讀了 HF 頁面上的摘要、作者留言和專案頁文字；論文方法細節、實驗設定、基準名稱（除 MathVerse 外）和統計檢定我都沒讀，所以無法評估 +6.6 分是否穩健。目前沒有第三方重現。

模型怎麼改自己

摘要描述 27B 模型『像人一樣』比較自己『有完成答案』與『跑到 token 上限還沒答完』兩種情況的隱藏狀態，找出區分兩者的方向，然後削弱它。專案頁的例子是模型在某題陷入一直重複『I will write the response.』的迴圈，修改後同一題、同一隨機種子能正常作答。

能力隨規模出現

同一家族四種大小給同樣的任務與工具，只有最大的 27B 能有效改進與修復自己；4B、9B 會把自己改壞。作者把這當成『能力隨規模湧現』的證據——這呼應今天 OpenAI 那則『新能力在某個門檻突然出現』的論點，但兩者是不同研究，我只是並列。

和『前沿模型改小模型』的差別

摘要提到先前已有前沿模型去編輯更小模型權重的研究；這篇強調是一個開放的 27B 模型改自己，不需要前沿模型也不需要訓練基礎設施。

要保留的疑問

『模型自己改權重』在安全上也值得關注：改動是否只修了特定失敗模式、會不會在其他任務退步，摘要沒有交代；修復實驗是人為破壞一小塊矩陣，和真實世界的退化不同。

觀察點

① 程式碼是否公開、有沒有人在其他模型家族重現；② 在寫程式等非數學任務上是否有效。

拿現成的影片生成模型教機器人『動作』：O²LaF 用同一個預訓練影片 DiT 同時初始化『從畫面猜動作』與『給動作生畫面』兩個模型，從無標註影片學到可跨機器人轉移的潛在動作

Yuxin Jiang、Mike Zheng Shou 等人提出 O²LaF（一個先驗、兩種動態）：潛在動作學習想從影片前後畫面的變化，反推出『造成變化的動作』當監督訊號，但過去多半從零學動態。O²LaF 讓兩個模型都從同一個預訓練影片擴散 Transformer（video DiT）初始化——一個是前饋式的『轉移編碼器』負責逆向動態（看兩張畫面→猜動作），一個是因果、以動作為條件的影片生成器負責正向動態（給動作→預測下一段畫面），兩者透過一個精簡的瓶頸端對端一起訓練。作者說在導航與機器人操作上，小樣本動作探測達到新的最佳，並能在不同視覺情境與不同機器人之間做零樣本動作轉移；換成 V-JEPA2 這類預測表徵當先驗也有競爭力。

逆向與正向動態

逆向動態（inverse dynamics）是『看到前後兩幀，推出中間做了什麼動作』；正向動態（forward dynamics）是『知道現在畫面和動作，預測下一幀』。兩者互為檢查：猜出的動作要能讓生成器畫出正確的下一幀。O²LaF 的重點是兩者共用同一份影片模型的先驗，並『控制資訊存取』，避免編碼器偷偷把整張下一幀塞進動作變數裡。

為什麼『可轉移』重要

如果學到的潛在動作只對某台相機、某種手臂有效，價值有限；作者宣稱能跨視覺情境與跨機器人型態做零樣本轉移，這是潛在動作方法想解的核心問題。是否成立要看全文實驗。

同日另一篇：PGX

arXiv cs.RO 的 PGX 走相反方向：不讓 VLA 一個模型包辦長時程任務，而是用『以物理條件判斷的狀態機』管流程、讓 VLA 只負責每個階段的技能、再用『世界座標鎖定』維持空間一致；在 3 個模擬任務和 1 個 Unitree G1 人形機器人真機任務上，作者說階段推進與成功率都有提升。兩篇並看：一個是從資料端讓模型學更多，一個是用傳統元件替模型分擔。

同事的改動讓 summary() 先拿鎖再呼叫也要拿同一把鎖的 all_orders()，而 threading.Lock 不可重入，造成死結；另一處把 .get() 改成直接取索引，找不到時丟 KeyError。agent 被限制只能用 Muru 工具、跑 tests.py、讀檔。它從堆疊看到 /orders/summary 已卡 29.9 秒、其他兩個請求排在後面，解釋了『失敗測試越跑越多』這個看起來像不穩定測試的現象，回滾後再修。作者強調：兩個版本並存，才讓 agent 能在當機『正在發生時』去看壞版本的 worker。

📘 今日一課 · 12 分鐘

成本與用量上限：替 App 裡的 AI 功能裝上『每人每日額度』和『每月預算』兩道閘門

為什麼今天學這個

第 6 週『把 AI 放進 App』已上過結構化輸出、端上 vs 雲端、資料最小化，今天補最後一個主題『成本與用量上限』。今天頭條 Dragos 的一句話剛好點題：『如果你不決定提示送去哪，最低價會幫你決定。』省錢的正確做法是控制用量，而不是改走來路不明的便宜轉售商——後者今天已證明會偷看提示。

是什麼

雲端模型按 token 收費，App 一上架，花多少錢就不再由你決定，而是由使用者怎麼用決定。『用量上限』就是幾道事先設好的閘門：① 每次請求的上限（max_tokens，限制單次輸出長度）；② 每位使用者每天能用多少；③ 整個 App 每月最多花多少；④ 供應商那端的硬上限，作為最後一道保險。

為什麼要分好幾層

只靠供應商的月上限，一個濫用的帳號就能把整個月的預算燒光，所有使用者一起停擺；只靠 App 裡的計數，程式有 bug 時又沒有保險。所以 App 端做『細』的額度（每人每天），供應商端設『粗』的上限（每月）。另外要記得：Tap Diary 不能把 API 金鑰放進 App 安裝檔，額度檢查一定要放在你自己的伺服器或代理上，否則使用者可以繞過。

Claude API 提供什麼

依 Claude 官方 Rate limits 文件：限制分兩種，spend limit（每月最多花多少）與 rate limit（每段時間最多幾個請求、幾個 token），採 token bucket 演算法持續補充。你可以在 Console 的 Spend limits 頁面為組織設一個低於所屬等級上限的月花費上限，也可以為每個 workspace 另設花費與速率上限——建議 Tap Diary 用獨立 workspace，避免和你自己的開發用量互相影響。每個回應帶有 anthropic-ratelimit-requests-remaining、anthropic-ratelimit-tokens-remaining 等標頭，可以拿來監控。

碰到上限時，錯誤長怎樣

這是最容易寫錯的地方。官方文件說：① 碰到等級的月上限，回 HTTP 429、type 是 rate_limit_error，但 error.details.error_code 是 enforced_spend_limit_reached，而且沒有 retry-after 標頭——重試（包括 SDK 的自動重試）都沒用，要到下個月 1 日 UTC 0 點才恢復；② 碰到你自己設的 spend limit，回 HTTP 400、type 是 invalid_request_error，訊息開頭是『You have reached your specified API usage limits』；③ 一般的速率限制是 429 且通常帶 retry-after，等指定秒數再試。所以程式要先分辨是哪一種，再決定『等一下』還是『停下來、改走離線模式、通知開發者』。

怎麼算每個人用了多少

每次 API 回應都會附 usage，包含 input_tokens 與 output_tokens。把它連同使用者 ID 與日期記下來，就能算每人每日用量；乘上官方價目表的單價就是成本。請求前先用『預估 token 數』檢查額度，回應後再用實際 usage 記帳。價格一定要從官方價目表抄，不要憑記憶——下方範例裡的單價是假設值。

動手做（勾選記錄進度）

範例檔案

"""每位使用者每日額度 + 全 App 每月預算 + 依官方錯誤格式決定要不要重試。"""
import sqlite3, datetime

PRICE_IN, PRICE_OUT = 3.0, 15.0     # 每百萬 token 美元：假設值，請改成官方價目表的數字
USER_DAILY_TOKENS = 20_000          # 每人每天最多用多少 token
APP_MONTHLY_USD = 30.0              # 自己訂的月預算（應低於 Console 的 spend limit）

db = sqlite3.connect(":memory:")
db.execute("create table usage(user text, day text, tin int, tout int)")

def cost(tin, tout):
    return tin / 1e6 * PRICE_IN + tout / 1e6 * PRICE_OUT

def allow(user, est_tokens):
    today = datetime.date.today().isoformat()
    used = db.execute("select coalesce(sum(tin+tout),0) from usage where user=? and day=?",
                      (user, today)).fetchone()[0]
    month = today[:7]
    spent = sum(cost(a, b) for a, b in db.execute(
        "select tin,tout from usage where substr(day,1,7)=?", (month,)))
    if used + est_tokens > USER_DAILY_TOKENS:
        return False, f"{user} 今日已用 {used} token，超過每日額度"
    if spent >= APP_MONTHLY_USD:
        return False, f"本月已花 ${spent:.2f}，達到 App 月預算"
    return True, "ok"

def record(user, usage):            # usage 取自 API 回應的 usage.input_tokens / output_tokens
    db.execute("insert into usage values(?,?,?,?)", (user, datetime.date.today().isoformat(),
               usage["input_tokens"], usage["output_tokens"]))

def on_error(status, body, headers):
    err = body.get("error", {})
    if status == 429 and err.get("details", {}).get("error_code") == "enforced_spend_limit_reached":
        return "停：組織月上限已到，重試沒用，App 改走離線模式"
    if status == 429 and "retry-after" in headers:
        return f"等 {headers['retry-after']} 秒再試"
    if status == 400 and err.get("message", "").startswith("You have reached your specified"):
        return "停：碰到自己設的 spend limit，通知開發者"
    return "其他錯誤：記錄後回報"

for i in range(6):
    ok, why = allow("alice", est_tokens=4_000)
    print(f"第 {i+1} 次週摘要請求：{'放行' if ok else '拒絕'}（{why}）")
    if ok:
        record("alice", {"input_tokens": 3_200, "output_tokens": 600})
print("alice 今日花費估計 $%.4f" % cost(3_200 * 5, 600 * 5))
print(on_error(429, {"error": {"type": "rate_limit_error", "details": {"error_code": "enforced_spend_limit_reached"}}}, {}))
print(on_error(429, {"error": {"type": "rate_limit_error"}}, {"retry-after": "12"}))

📚 今日新名詞

金絲雀憑證（canary token）只放在一個地方的假鑰匙或網址，一旦有人使用就會通知你，代表那個地方被看過或外洩了。
零資料保留（ZDR）供應商承諾不儲存你的提示與回應；Dragos 發現它只約束第一站，後面的轉手不一定遵守。
推論路由器／市集用一個 API 端點把請求轉給多家模型供應商的服務；市集版本由最便宜的賣家接單，每一層轉手都看得到全文。
困惑度（perplexity）衡量模型猜下一個 token 準不準的分數，取 log 就是交叉熵損失，越低越好。
思考鏈監控（CoT monitor）讀模型推理過程的文字，判斷它有沒有在做不該做的事；OpenAI 認為需要更強的後繼方法。
隱藏狀態（hidden states）模型內部每一層對輸入算出的向量，可以拿來分析模型『在想什麼』。
潛在動作（latent action）從影片前後畫面變化中學出來、不需人工標註的『動作』表示，可當機器人學習的監督訊號。
逆向／正向動態逆向：看前後畫面推出動作；正向：給目前畫面和動作預測下一幀。
影片 DiT以 Transformer 為骨幹的影片擴散生成模型，學過大量影片，懂『世界怎麼變化』。
邊際排放新增用電時，實際被叫起來多發電的那些電廠的排放；通常比電網平均更高。
WSGI／ASGIPython 網頁應用和伺服器之間的標準介面；WSGI 是同步的老標準，ASGI 支援非同步。
Spend limit（花費上限）在 Claude Console 為組織或工作區設定的每月花費上限，到了請求就會被擋。
