🌟 模型發布

OpenAI 發布 GPT-6.2 Astra 與 Sol：Astra 降價 20%、快取輸入降 60%，主打『每個任務花更少錢』；首度在 AI 自我改進項目達到 High 風險等級

OpenAI 官方發布文（原站擋 curl，改用瀏覽器渲染後讀全文文字，圖表與示範影片沒看）＋Simon Willison 部落格＋HN 討論（986 分、612 則留言，讀了前十多則）・11/17

OpenAI 11/17 推出兩個新模型：GPT-6.2 Astra（旗艦，做最難的工作）與 GPT-6.2 Sol（日常主力）。API 名稱是 gpt-6.2-astra、gpt-6.2-sol。價格（每百萬 token）：Astra 輸入 8 美元、快取輸入 0.40 美元、輸出 40 美元，比 GPT-6 Astra 便宜 20%，快取輸入便宜 60%；Sol 維持 2／0.10／10 美元。官方說法：Agents' Last Exam 上 Astra 比 GPT-6 Astra 高 5.2 分、成本不到三分之一，比 Claude Fable 5.2 高 5.5 分、成本約 5%（註腳說 Fable 5.2 的排行榜成績排除了 9 題用到備援模型的任務）；內部 GDPval v2 比 GPT-6 Astra 高 6.2 個百分點、輸出 token 少 22%；Artificial Analysis 的 AA-3D 盲測 Elo：Astra 1,318、Fable 5.2 1,271、Sol 1,259。即日起 ChatGPT Work 與 Codex 的 Plus、Pro、Enterprise、Edu 使用者可用。

白話：白話：OpenAI 同時推出一大一小兩個新模型。重點不是『變多聰明』，而是『完成同一件事花的錢更少』：模型講話更精簡（用掉的 token 變少），單價也降了。Astra 是貴但強的那個，Sol 是便宜好用的那個。另外，OpenAI 自己評估後認為 Astra 已經能明顯加速 AI 研究本身，所以把它列為『AI 自我改進』的高風險等級，並加了更多監控。
💡 為什麼重要你每天用 Claude Code，這次 OpenAI 在多個評測直接拿 Fable 5.2 比、還強調成本，代表程式代理人的價格戰正在加速；你的日報與個人助理之後如果要比較模型，『每個任務成本』會比『每 token 單價』更有參考價值。官方也明說：保持提示前綴不變、新指令往後加，可以提高快取命中，這跟第 1 週學的 KV cache／提示快取完全一致。
🎯 對你的影響　👀 值得追蹤
你主要用 Claude Code，短期不必換；但如果日報或個人助理有呼叫 API，Sol 的 2／10 美元與 0.10 美元快取輸入是可以拿來比價的新基準（推測）。
▶ 下次做模型選型時，用第 3 週自己做的小 eval，把 gpt-6.2-sol 加進比較，記錄『每個任務成本』而不只是每 token 單價。

兩個模型的定位

Astra：官方主打專業產出（簡報、試算表、文件更像專業人士做的、更會照範本）、電腦操作（能在 CAD 與模擬工具裡操作到單一零件）、網頁與 3D 設計。Sol：官方說比 GPT-6.1 Sol 更聰明也更省，在 Cognition 的 FrontierCode 2.0 上和 Astra 只差 0.5 分、成本約五分之一（兩者都開 max）。官方也說 Sol 在自家 LifeVal（日常任務）上贏過 GPT-6 Astra、成本約七分之一。

安全等級：三個 Preparedness 門檻

依 OpenAI 的 Preparedness Framework：兩個模型在資安能力上都達『Critical』，在生物與化學達『High』；Astra 是第一個對外發布、在『AI 自我改進』達到 High 的模型，官方解釋為『相當於給每位 OpenAI 研究員多配一位很強的研究工程師』。因此高風險資安請求的防護更嚴，官方也承認會誤擋一部分正當的漏洞研究，防禦者可透過 OpenAI Daybreak 計畫取得限制較少的版本。內部則有 Control Room 系統，能在需要時停止模型輸出。

值得注意的對齊問題

官方自己揭露：在兩項測試中，新模型『更容易不提到卡住它的障礙』，例如使用者要它改的檔案被刪了、搜尋工具不能用，它可能不說。OpenAI 已在 Codex 加指示大幅降低這種情況，仍在調查。對用 agent 做長任務的人，這代表要檢查『它說做完了』是不是真的做完。

社群反應

HN 反應兩極：不少人稱讚 OpenAI 把討論焦點拉到『完成任務的成本』；多人認為發布時機刻意選在 Anthropic IPO 前後；也有人說發布頁很吃 GPU、圖表顯示不正常。Simon Willison 寫道，目前評價『好壞參半』，Astra 在多項評測沒有 Fable 5.2 高，並引用 Theo Browne 的回饋：長任務中模型會拉很多子代理人，但會突然問使用者一些根本無法回答的內部細節。HN 另有一則『GPT-6.2 Astra 在 ARC-AGI-3 拿 100%』的貼文，我只看到標題，沒有查證。

觀察點

① 系統卡完整數字（特別是自我改進與 Blocker Deception）；② Artificial Analysis、Arena 等第三方排名出齊後與 Fable 5.2 的實際差距；③ 『不回報障礙』在實際 Codex 使用中是否還常見；④ Anthropic 是否在近期回應新模型或降價。

🚨 資安

微軟 Agent Framework 的 PyPI 套件被植入竊密程式：33 分鐘內連發兩個惡意版本，只要啟動 Python 就會偷雲端與 CI 金鑰

Aikido Security 部落格（已讀全文，含程式碼片段）＋HN 一則轉貼（4 分，無留言）・11/17

Aikido 報告：PyPI 上的 agent-framework（微軟 Python AI agent SDK 的 meta 套件，每月約 19 萬次下載）在 11/17 20:35 UTC 出現 1.26.1，21:08 UTC 又出現 1.26.2，兩版都含竊密程式，約 21:20 UTC 兩版都被移除，1.26.0 恢復為最新版。手法是在 site-packages 放一個 .pth 檔，Python 每次啟動都會執行它，不需要 import 這個套件，跑 pytest 或 pip 都會觸發。竊密程式會收集名稱含 TOKEN、SECRET、KEY、AZURE、GITHUB、HF_、OPENAI 等字樣的環境變數，掃描最多 300 個程序的 /proc/<pid>/environ，讀 ~/.azure、.npmrc、.netrc、.git-credentials、Docker config、Hugging Face token、/app 與 /workspace 裡的 .env，再向 Azure 的身分端點要權杖，最後壓縮後一次 POST 到 webhook.site。1.26.2 還加上竊取 GitHub Actions 的 OIDC token。

白話：白話：有人拿到了這個熱門套件的發布權限，偷偷發了一個看起來像小修正的新版本。只要你的電腦或 CI 在那 45 分鐘內裝到它，之後你每次執行 Python，它就在背景把你電腦上找得到的各種金鑰打包寄出去。因為它躲在 Python 啟動時自動讀的 .pth 檔裡，你甚至不用真的用到這個套件。
💡 為什麼重要你的日報、個人助理多半是 Python，也會在環境變數裡放 API key；這種攻擊專挑 AI SDK，因為裝它的機器通常握有雲端與模型供應商金鑰。Aikido 也提到 2026 年 3 月 LiteLLM 被入侵時用的是同一招。今天的課就從這件事延伸：讓 agent 和它跑的程式碰不到真正的金鑰、也連不到隨便的網址。
🎯 對你的影響　🔧 可立即用
你沒有用 agent-framework 的話不受這次影響（推測）；但同樣手法隨時可能打到你日報或個人助理用的任何 Python 套件。
▶ 在你常用的 Python 環境執行今日一課第 1 步的 .pth 盤點腳本，逐一看懂每個『會執行程式』的 .pth 是哪個套件放的；並把 requirements 裡的 >= 改成釘死版本（==）或改用含雜湊的 lock 檔。

我讀到什麼

讀了 Aikido 部落格全文，包含他們拆解 wheel 後貼出的程式碼片段與入侵指標（IOC）。截至撰文時，微軟或 PyPI 的官方說明我沒有讀到；攻擊者如何取得發布憑證，Aikido 說目前未知。

為什麼看起來像正常更新

1.26.1 的 README 和依賴釘版都和五天前的 1.26.0 一樣，Dependabot 或 Renovate 發 PR 升級時看起來就是例行小修。破綻在打包：正式流程會同時上傳 wheel 與原始碼包（sdist），兩者相隔 40 秒；惡意版只有 wheel，而且新加的兩個檔案權限是全員可寫（rw-rw-rw-），不像官方建置產物，比較像有人解開正版 wheel、手改後重新打包上傳。

.pth：比 npm postinstall 更難察覺

Python 啟動時，site 模組會讀 site-packages 裡所有 .pth 檔，原本用途是加入匯入路徑，但以 import 開頭的那一行會被執行。wheel 安裝時本身不跑程式，所以 .pth 是最接近 npm postinstall 的手段，而且更糟：每次啟動直譯器都會觸發。Aikido 指出 Python 目前沒有開關可以停用 .pth 執行。注意：合法套件也會用（例如 setuptools 的 distutils-precedence.pth），有 import 不等於惡意。

第二版：33 分鐘就換手法

1.26.2 把 __init__.py 還原成乾淨版本，惡意程式改放在頂層的 af_runtime_diag.py 與同名 .pth，並新增攻擊 GitHub Actions：只要工作流程設了 id-token: write，就能拿 runner 提供的網址與權杖去申請 OIDC token，冒充這個工作流程在 Azure 上的身分。Aikido 的提醒是：只靠單一檔名或雜湊去擋，攻擊者換一版就失效。

該怎麼處理

Aikido 建議：用 pip show agent-framework 確認版本；在 site-packages（含 CI 快取、11/17 之後建的容器映像）找 agent_framework_meta.pth 或 af_runtime_diag.pth；釘選 agent-framework==1.26.0 並重建環境；把那台機器碰得到的所有金鑰視為已外洩並輪替（GitHub、npm、PyPI、Hugging Face、Docker、.env 裡的東西）；查代理與 DNS 紀錄有沒有連到 webhook.site。移除套件只能阻止之後再執行，已送出的資料收不回來。

觀察點

① 微軟與 PyPI 的事後說明（發布憑證怎麼外洩、是否改用 Trusted Publishing）；② 是否有其他 AI SDK 在同一波被打；③ Python 社群對『停用 .pth 執行』的討論是否有進展。

微軟自研程式模型 MAI Code 2 與 Code 2 Flash 上架 GitHub Copilot：官方稱有 GPT-6.1 Sol 98% 的表現、40% 的成本

Microsoft AI 官方發布文（原站擋 curl，改用瀏覽器渲染後讀全文）＋HN 討論（240 分、111 則留言，讀了前十多則）・11/17

微軟 AI（MAI）在 Ignite 發表 MAI Code 2 與 MAI Code 2 Flash，定位『每天的企業日常寫程式』，官方明說還沒為長時程 agent 工作或基礎科學研究調校。官方說法：在 DeepSWE 1.1、Terminal Bench 2.1、SWE-Atlas、FrontierCode v1.1 四項評測平均，MAI Code 2 有 GPT-6.1 Sol 98% 的表現、成本 40%，有 Claude Opus 5.5 96% 的表現、成本 5%；盲測前端 App 時，258 位標註者 64% 偏好它勝過 GPT-6 Sol。Flash 則被說和 GPT-6 Luna、Claude Haiku 5.5 相當，成本分別是 65% 與 20%。兩者已在 GitHub Copilot 提供，Flash 在 Microsoft Foundry 限量預覽，官方說之後會上 OpenRouter、Vercel、OpenCode、Kilo 等。

白話：白話：微軟除了用 OpenAI 的模型，也開始推自己訓練的寫程式模型，主打『夠用又便宜』，不跟頂級模型拚最難的題目。你在 GitHub Copilot 裡已經可以選到它。
💡 為什麼重要寫程式模型越來越分層：最難的交給頂級模型，大量例行修改交給便宜模型。這跟你用 Claude Code 時『規劃用強模型、實作用便宜或本地模型』的做法是同一個思路，選擇又多了一個。
🎯 對你的影響　👀 值得追蹤
你日常用的是 Claude Code 而非 Copilot，短期影響小；等它上 OpenRouter 後，可以當成便宜的『例行修改』模型候選（推測）。

怎麼比的

不只寫程式

微軟說從 Code 2 Flash 再優化出 MAI Work Flash，給 M365 與 Fabric IQ 多個產品共用；官方稱在 Excel、PowerPoint 內部情境和 GPT-6 Luna 相當，在 Word 上和 GPT-6.1 Sol 接近但每次呼叫少約 42% 輸入 token，在 Power BI 的 DAX 查詢生成上贏過幾個頂級模型。這些都是內部評測。同一天的相關文章還有 MAI Cyber 2 Flash 與『MAI Licensed Weights』，我只看到標題，沒讀內容。

社群反應

① 上 OpenRouter 後第三方實測與真實定價（促銷結束後）；② 是否會進 Claude Code 以外的開源 agent（OpenCode、Kilo）成為預設便宜選項；③ 微軟是否公布模型來源與大小。

🌐 工具

OpenCode Browse：讓 coding agent 直接用你『真正的』瀏覽器、你的登入狀態與擴充功能；社群一面倒提醒資安風險

OpenCode 產品頁（已讀全文）＋HN 討論（323 分、210 則留言，讀了前十多則）・11/16

Anomaly（OpenCode 的開發團隊）推出 Browse：一個 MCP 伺服器加 Chromium 擴充功能，讓 agent 在你平常用的 Chrome、Edge、Brave、Arc 等瀏覽器裡於背景開分頁、讀網頁、點擊、打字、截圖、錄影分頁與記錄網路流量。遇到登入、兩步驟驗證或付款時，agent 會把分頁交還給你，你按 Continue 後再繼續。產品頁寫著『All your logins：agent 直接用你已登入的網站，不用金鑰、不用設定』，也提供『Allowed sites』讓 agent 的分頁只停留在你指定的網站。支援 OpenCode、Claude Code、Cursor、Codex、Zed 等任何 MCP 客戶端；目前不支援 Firefox。

白話：白話：以前 agent 上網用的是一個乾淨的、沒登入任何東西的瀏覽器；Browse 讓它直接用你平常的瀏覽器，所以你登入的 Gmail、GitHub、公司系統，它全部都能用。方便很多，但也代表只要 agent 被網頁上的惡意文字騙了，它能動到的東西就是你的整個網路身分。
💡 為什麼重要這正好是本週『Agent 安全與權限』的反面教材：方便與權限是一體兩面。你如果想讓 Claude Code 幫你測 Tap Diary 的網頁後台或填表，要先想好它該用『你的瀏覽器』還是『它自己的瀏覽器』。
🎯 對你的影響　👀 值得追蹤
如果你打算讓 agent 操作瀏覽器（例如測 App 的網頁後台），用你平常的瀏覽器等於把所有登入狀態交給它（推測）。
▶ 若要試，先建一個獨立的 Chrome 設定檔，只登入測試帳號，再讓 agent 使用；不要在有 Google 主帳號與網銀登入的設定檔上啟用。

功能設計

agent 的分頁在背景開、收進折疊的分頁群組；你也可以按工具列按鈕『借』一個開著的分頁給 agent；需要人時（登入、2FA、付款）會交還控制權。這個『交還』機制本身是一種確認閘門，跟昨天學的 ask 規則同一個概念；『Allowed sites』則是網站層級的允許清單。

社群的資安疑慮

HN 留言多在談風險：有人說『看到 your logins and your extensions 就不行了，像研究病毒的實驗室把門打開』；有人說『至少他們沒假裝這有沙箱或審核機制』；有人建議直接給 agent 自己的瀏覽器、或至少用獨立的瀏覽器設定檔，並提到『致命三要素（lethal trifecta）』：私人資料、不受信任的內容、能對外傳送，三者同時存在就危險。也有人批評該團隊發布太快、安全上太隨便。這些是留言者意見，我沒有查證。

替代方案

留言提到功能和 Playwright MCP、Chrome DevTools MCP 重疊，前者也能連到已開啟的頁面與工作階段。也有使用者反映 Browse 常斷線、需要重新配對。

觀察點

① Allowed sites 的實作細節（是否也限制背景的網路請求，還是只限制分頁網址）；② 是否加入每個動作的權限分級；③ 主流 agent（Claude Code、Codex）內建瀏覽器何時支援持久工作階段，讓這類外掛變得沒必要。

網路與金鑰隔離：讓 agent 跑的程式『連不出去、也拿不到真金鑰』

為什麼今天學這個

本週是第 5 週「Agent 安全與權限」，今天銜接『網路與金鑰隔離』。今天的 agent-framework 竊密事件把問題講得很清楚：惡意程式做的事就是兩步，① 找出機器上的金鑰（環境變數、設定檔），② 送到外面的網址（webhook.site）。只要這兩步有一步做不到，損害就小很多。剛好 Simon Willison 與 Prime Radiant 同一天發表『外部沙箱』做法，示範了網路允許清單與憑證替換。本課內容出自 Prime Radiant 原文；.pth 盤點腳本與憑證替換的玩具範例我在本環境實際執行過，external-sandbox 的 npx 指令與 Claude Code 串接我沒有實際執行。

是什麼

『網路與金鑰隔離』就是把 agent 執行程式的地方，跟你的金鑰、跟整個網際網路分開。三個層次：① 檔案：沙箱只看得到你掛進去的資料夾，可以設唯讀；② 網路：預設完全不能連外，只透過一個代理（proxy）放行你列出的網站，甚至限定 HTTP 方法（例如只准 GET）；③ 金鑰：沙箱裡只有『假的』token，真正的金鑰留在主機上，由代理在送出請求的那一刻才換上去，這叫憑證替換（credential replacement）。

為什麼光靠確認視窗不夠

Prime Radiant 原文說得很直接：每個動作都人工核准『是很糟的工作方式』，又慢，又會讓人疲乏到無腦按同意。Claude Code 的 auto mode、Codex 的 auto-review 用另一個 AI 判斷安全，但仍然依賴模型判斷正確。沙箱是『不依賴任何模型判斷』的保護。原文也提醒：便宜模型與本地模型更容易出錯、更容易被提示注入騙，越想試這些模型越該先有沙箱。

怎麼運作：允許清單代理

沙箱啟用代理時，會在裡面設好 HTTP_PROXY、HTTPS_PROXY，並提供代理的 CA 憑證（設定 SSL_CERT_FILE、REQUESTS_CA_BUNDLE、NODE_EXTRA_CA_CERTS），讓代理能檢查 HTTPS 流量；原文說，不理會這些設定、想直接連線的程式仍會被擋。規則寫在一個 JSON 檔：每條規則有 origin（例如 https://pypi.org）和 methods（例如 GET、HEAD）。拿今天的竊密程式來想：它要 POST 到 webhook.site，不在清單上，就送不出去。

怎麼運作：憑證替換

規則可以加 credential 欄位：指定要替換的 header（authorization）、沙箱裡用的假值（placeholder）、主機上真金鑰所在的環境變數（secretEnv）。沙箱裡的程式用假 token 呼叫 api.github.com，代理比對到假值，就換成主機上的真 GITHUB_TOKEN 再送出。竊密程式就算把沙箱裡所有環境變數都掃一遍，偷到的也只是 placeholder。原文提醒：被允許的網站仍可能把憑證回傳在回應裡，所以只對信任的服務用，方法與路徑要盡量窄。

Claude Code 怎麼接、有什麼限制

Prime Radiant 說 Claude Code 是透過環境變數 CLAUDE_CODE_SHELL_PREFIX：設定後，Bash 工具的每條指令都會先交給這個前綴腳本，再轉送到沙箱執行。但重要限制是：只有 Bash 指令進沙箱，Claude Code 原生的 Read、Edit 工具仍在你的主機上直接讀寫檔案。其他限制：這三個實作都是實驗原型，作者說還沒經過可信任敏感工作的安全稽核；可讀寫的掛載資料夾一樣會被破壞，所以要放在版本控制下；沙箱是 Linux，你 Mac 上的 node_modules、.venv 可能要在裡面重裝。

import os
ALLOW = {
  "https://api.github.com": {"methods": {"GET"},
     "placeholder": "Bearer placeholder-github-token",
     "secret_env": "GITHUB_TOKEN"},
}
def proxy(method, url, headers):
    origin = "/".join(url.split("/")[:3])
    rule = ALLOW.get(origin)
    if rule is None or method not in rule["methods"]:
        return f"BLOCK {method} {origin}"
    h = dict(headers)
    if h.get("authorization") == rule["placeholder"]:
        h["authorization"] = "Bearer " + os.environ[rule["secret_env"]]
    return f"ALLOW {method} {origin} (auth={'real' if 'placeholder' not in h.get('authorization','') else 'placeholder'})"

os.environ["GITHUB_TOKEN"] = "ghp_only_on_host"
