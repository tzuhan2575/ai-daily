Anthropic 與美國政府採購署擴大合作：政府客戶 Claude 全產品 4 折優惠

Anthropic・10/27

官方公告（10 月 27 日）說，與美國聯邦政府採購署（GSA）簽了新協議：政府單位購買 Claude Enterprise、Claude for Government 與 Claude API 可享 40% 折扣，首次涵蓋所有產品介面（現在直接向官方買，未來數月也包含經由雲端供應商購買），並延伸到州、地方、部落與領地政府。官方估計折扣能替政府省下 10 億美元；機關沒有最低消費承諾，用多少付多少。官方並說約 500 個美國聯邦、州與地方政府組織在使用 Claude，Claude for Government 的每週活躍用戶自 2 月起成長約八倍，聯邦文職機關用量一年成長約 20 倍。

白話：政府採購有固定的採購合約平台，廠商要列在上面機關才方便買。這次是官方把價格壓低 4 成並放寬到各級政府，目的是讓政府單位不用先簽大額合約就能開始試用。
💡 為什麼重要這則跟你的日常使用沒有直接關係，但它透露 AI 廠商在企業與公部門的競爭方式：用折扣與免最低消費降低試用門檻。另外官方列的案例（用 Claude Code 把大量舊程式碼轉移框架、替舊系統寫文件）正是 AI 輔助開發最實際的用法，可當作自己專案的參考。

協議內容

我讀到的是官方公告全文：40% 折扣適用於 Claude Enterprise、Claude for Government 與 Claude API；機關可經 GSA 的多重授標合約表（Multiple Award Schedule）以 OneGov 折扣購買；官方另會推出協助機關導入的專屬計畫，說是會在數週內帶入企業客戶常用的做法。

官方數字（皆為官方自述）

約 500 個政府組織在用；每週活躍用戶自 2 月起約成長八倍；聯邦文職機關用量一年約 20 倍；折扣估計可省 10 億美元。這些數字沒有第三方驗證，估算基準公告也沒有說明。

官方列舉的案例

猶他州讓 10 個機關的 34 位開發者使用 Claude Code：80% 在 30 分鐘內有可用環境，71% 回報在為期四週的試辦中省下 20 小時以上。某州 IT 開發者在兩天內把近 900 個 API 方法移到新框架，原本預估要一個月。某州 IT 主管用 Claude Code 為 12 個舊程式庫寫文件，對應 467 張資料表並標出 27 項風險。另有某州資訊長說團隊處理勒索軟體攻擊只花 8 分鐘，平常要 2 到 3 天。這些都是官方轉述客戶說法，細節（如何計時、樣本）公告沒有交代。

資安相關說法

公告稱聯邦資安團隊用某個資安模型在約兩天內找到並修補一個可能導致關鍵正式系統被接管的漏洞，前一個月的人工滲透測試沒有發現。同樣是官方說法，無獨立驗證。

合規與部署

官方說 Claude for Government 於 9 月 30 日正式推出，在 FedRAMP High 授權等級提供接近商用版的功能。透過 Amazon Bedrock 為 FedRAMP High，部分模型在 AWS GovCloud 獲 DoD IL4／IL5 授權；透過 Google Cloud Vertex AI 為 FedRAMP High。Claude Enterprise 正透過 FedRAMP 20x 計畫申請 FedRAMP Moderate。

我沒讀到的部分

沒有看到協議本文、折扣是否有期限、與其他廠商同類協議的比較，因此不判斷這是否為同業最低價。

Anthropic 公開徵求生命科學「客座研究者」：8 到 12 週免費合作

Anthropic・10/22

官方公告（10 月 22 日，本期補報）邀請學術機構、非營利或政府實驗室的主持研究者提案，主題含人類因果生物學、結構與計算分子生物學、藥物化學、藥物發現與臨床科學。入選者與官方研究員合作 8 到 12 週，官方免費提供模型與工具框架（harness），雙方合作發表成果並開源相關資料與程式碼；研究者保有資料權與後續獨立研究的權利。申請期約 14 天，結束後約 14 天內通知入選者。

白話：簡單說，這是一個『免費借用 AI 與研究團隊』的限期專案，要求提案者說明為什麼需要直接合作，以及短時間內能做出初步證據。
💡 為什麼重要與你的 CV／機器人背景與目前專案都無關，但它顯示 AI 公司正把『模型＋自家研究員』當成服務送給科學界，而不只賣 API。

要求與條件

申請人需說明如何從與官方研究員直接合作中受益，且合理說明 8 到 12 週內能產出初步發現、開放資料集或公共資源等成果；部分專案可能延長。公告承認多數開放問題的驗證需要更久。

資料與隱私

官方不要求提供資料，也要求申請材料只含公開資訊；研究者在每個階段保留資料權。

其他相關計畫

公告提到還有 Life Sciences Verification Program（讓科學家取得官方最強的公開生物模型）與 AI for Science（提供 Claude 額度），並說這是加碼投入生命科學的多項行動之一；前述計畫細節我沒有讀。

觀察點

KV cache 與提示快取：為什麼重複的前綴可以便宜很多

為什麼今天學這個

課程第 1 週接著 KV cache。前兩課談 token 計價與上下文視窗，這課解釋為什麼 Claude Code 的長對話不用每輪都從頭付全額。

是什麼（背景知識）

Transformer 模型生成每個新字時，要用到前面所有字的 key 與 value 向量。把它們存在記憶體裡重複使用，就叫 KV cache，這樣不用每生成一個字就把整段前文重算一遍。這段是一般原理說明，不是來自下面的官方文件；官方文件談的是下一節的 API 功能。

API 層級：提示快取

官方文件說，提示快取讓你從提示的某個前綴『接續』處理，能降低處理時間與成本。系統會先檢查到指定斷點為止的前綴是否在近期查詢中被快取；有就用快取，沒有就處理完整提示，並在回應開始後快取該前綴。（文件沒有說明內部實作是否為 KV cache，兩者的關係是我的推測。）

快取的是什麼順序

文件說快取參照整份提示，順序是 tools、system、messages，到你標示 cache_control 的區塊為止。所以要把不常變的內容（工具定義、系統指示、範例）放前面，變動的放後面；前綴中任何一處改動，後面的快取就失效。

兩種開法

自動快取：在請求最上層加一個 cache_control: {type: ephemeral}，系統會把斷點放在最後一個可快取區塊，對話變長時自動往後移，適合多輪對話。明確斷點：直接在個別內容區塊上標 cache_control，細緻控制要快取哪些。

價格與存活時間

依文件：5 分鐘 TTL 的寫入是基本輸入價的 1.25 倍；1 小時 TTL 寫入是 2 倍；讀取（命中）是 0.1 倍，但 Opus 5.5 與 Sonnet 5.5 是 0.05 倍，Fable 5.1 與 Mythos 5.1 是 0.025 倍。預設存活 5 分鐘，每次命中免費刷新。

門檻與怎麼確認有沒有命中

文件說太短的提示不會被快取也不報錯：Opus 5.5、Sonnet 5.5、Haiku 5.5 等的最小可快取長度是 512 token（其他模型有 1,024、2,048、4,096 等不同值）。判斷方式看回應 usage：cache_creation_input_tokens 與 cache_read_input_tokens 都是 0，代表沒快取；總輸入 = cache_read + cache_creation + input_tokens，其中 input_tokens 只算最後一個斷點之後的部分。

和上下文視窗的關係

前一課提到：快取只改變計價與速度，不會讓這些 token 不佔視窗。我沒有實際呼叫 API 驗證，以上取自官方文件。

動手做（勾選記錄進度）

貼給 Claude Code 的指令

請依 Anthropic 官方文件「Prompt caching」，用白話向我解釋：1) 提示快取如何運作、快取的順序（tools、system、messages）2) 自動快取與明確斷點的差別 3) 5 分鐘與 1 小時 TTL 的寫入與讀取價格倍率 4) 如何從 usage 欄位判斷有沒有命中。再幫我在目前專案找出適合放進快取前綴的固定內容，並寫一個最小範例腳本印出 usage。請標明哪些是官方文件說的、哪些是你的推測，並說明你有沒有實際執行。
