Gemini 4 Carbon 全面開放：官方說是最強模型，定價與 Argon 相同（輸入 2 美元、輸出 10 美元／百萬 token）

Google DeepMind 官方部落格（已讀大部分，後段略讀）・11/10；HN 討論（只看標題與分數 266 分、145 則留言）

Google 11/10 宣布 Gemini 4 Carbon 對開發者、企業、科學家與一般用戶開放。官方定位：資安與長時程 agent 工作流（複雜知識工作、軟體工程、科學推理）表現最強；Argon 仍適合多數工程與知識工作，Carbon 用在更吃智力的任務，會花更多 token 做深度推理與反覆驗證。API 走 Google AI Studio 與 Gemini for business（付費層），介紹性定價與 Argon 相同：每百萬 token 輸入 2 美元、輸出 10 美元；Ultra 訂閱者可在 Antigravity、Gemini app、AI Mode 使用。官方稱在 CursorBench 4.0、Perplexity 的 WANDR、Zapier 的 AutomationBench 排名第一，每任務成本比次佳外部模型低 2 倍以上；與 Artificial Analysis 合作的新基準 MKA（多模態知識 agent）排第二，但每任務平均成本比第一名低 6 倍以上。同時預覽 Antigravity 的 /swarm：一個提示展開成一組可即時追蹤的多 agent 團隊。以上皆為 Google 自己的說法，我沒有讀到各基準的原始報告。

白話：白話：Google 把它最聰明的模型開放給大家用，價格跟次一級的 Argon 一樣；重點賣點是『做長而複雜的工作，並自己反覆檢查』，而且官方說同樣的任務花費比競品便宜。
💡 為什麼重要你日常靠 Claude Code 做 agent 式開發，Carbon 與 /swarm 是同類競品：『大模型負責架構與審查、小模型平行幹活』的分工，正是你自己的 agent 流程可以參考的結構。是否值得換，要用你自己的任務比，不要只看榜單。

定價與取得方式

每百萬 token 輸入 2 美元、輸出 10 美元，官方標註為『介紹性價格』，與 Argon 相同。付費開發者與企業可用；Ultra 訂閱者可在 Antigravity、AI Studio、Gemini app、AI Mode 用到。

成本主張怎麼讀

官方強調『每任務成本』而非每 token 單價：在三個外部基準排第一且成本低 2 倍以上；MKA 排第二但便宜 6 倍以上。基準由第三方公司設計，但成本數字的計算條件我沒看到，且 Carbon 本身設計成多花 token 推理，所以請以自己任務實測的總花費為準。

/swarm 與多 agent

官方描述可把最深推理的角色（架構、協調、審查）給 Carbon，搭配較快較輕的模型在平行、隔離的工作區工作，並有對抗式驗證者測每個變更。示範包含用 Three.js 重建場景等，皆為官方展示，沒有獨立重現。

資安能力

官方說 Carbon 在找洞（SEC-bench Pro）、寫利用（ExploitGym）、修補（CWE-bench v1）領先，但這是透過 Fairwind 計畫提供給防守方使用；自家 Project Fortify 內部基準上掃描召回 100%、分流精準度 95%（內部基準）。官方也舉例：安全團隊用它在兩家大型 SaaS 供應商找到 0-day，並與對方修補。

安全與防護數字

官方稱模擬網攻環境中擋下 99% 攻擊軌跡，單次突破率 0.8%（Argon 為 3.1%）；外部測試 132 小時、1.3 萬次請求沒有新的通用越獄；Gray Swan 間接提示注入基準攻擊成功率 0%，但官方自己也說提示注入仍待改善。以上都是官方或其委託方的說法。

觀察點

第三方（例如 Artificial Analysis）獨立測的整體分數與真實成本；多 agent 的 /swarm 在你自己的 repo 上品質如何；以及 Carbon 與 Fable 5.2 的實際工作對比。

影響範圍

Notion 說不到 1% 的工作區可能受影響；沒收到通知的工作區代表未受影響。受影響工作區的擁有者已被聯絡，可在側欄『Security incident review』檢視並下載受影響資料（需桌面瀏覽器）。

什麼資料

『無法歸屬』指對話沒標作者或工作區，且不含工具呼叫結果（例如 Notion 頁面內容）。但 Notion 也說，對話文字本身可能含敏感資訊，因此建議視為已外洩。

Notion 怎麼用 Fireworks

用於 Insights 功能的分類工作，以及作為一般推論供應商提供產品內的開放權重模型；也提到過去曾在其上用志願參與者（LEAP 計畫）提供的資料實驗訓練特定任務模型。

給開發者的教訓（我的整理）

一、不要把金鑰、密碼貼進任何 AI 對話；二、自己的產品要盤點哪些使用者文字會送到哪個推論供應商；三、能不送就不送，或先去識別。這三點是我依此事件的歸納，不是 Notion 原文。

Fireworks 公布的完整調查結果；其他使用同一供應商的公司是否也發聲明；入侵方式是否涉及更廣泛的供應鏈問題（目前我沒有看到來源說明）。

資料外送盤點：哪些文字會離開你的機器、要不要自己跑

為什麼今天學這個

今天 Notion 的第三方推論供應商外洩，加上 Apple Harbor 傳聞主打『資料不離開自己的硬體』，銜接第 4 週「本地跑小模型」的收尾：什麼情況下值得本地跑，要先知道自己有哪些資料會外送。事件內容出自 Notion 官方說明頁；下面的盤點步驟是我整理的一般做法，不是官方文件，指令未在此環境實際執行。

是什麼

『資料外送盤點』是列出你的程式把哪些文字、送給哪個外部 AI 服務。本地跑模型只是解法之一，先盤點才知道需不需要。

為什麼重要

Notion 的說明頁顯示，他們把分類工作與部分開放權重模型的推論交給 Fireworks，供應商出事後，部分 AI 對話被取走。Notion 的建議是把這些資料當成已外洩，並輪替貼過的金鑰。也就是說，資料離開你的系統的那刻起，安全就取決於整條鏈上每一家。

三個層次

一、送了什麼：使用者輸入、系統提示、檔案內容、工具結果；二、送給誰：你的直接供應商，以及它背後的供應商；三、留多久：供應商是否保存、是否拿去訓練（要看服務條款，我沒有替你查）。

本地跑 vs 雲端的取捨

本地：資料不出機器，但你自己負責品質、更新與硬體成本（前幾課講過 GGUF、量化與硬體估算）。雲端：品質與維運省事，但要信任供應商。常見折衷（我的整理）：敏感欄位本地處理或先遮蔽，其餘才送雲端。

10 分鐘小實作

在專案目錄搜尋所有呼叫外部 LLM 的位置，逐一填一張表：位置、送出資料、是否含個資或金鑰、供應商。表格填完，你就知道哪些該先改。

動手做（勾選記錄進度）

貼給 Claude Code 的指令

請用繁體中文幫我做『資料外送盤點』。在目前專案中搜尋所有呼叫外部 LLM 或第三方 AI 服務的程式位置（包含 SDK、HTTP 請求、環境變數中的 API 金鑰名稱），不要修改任何檔案。輸出一張表：檔案與行號、送出的資料內容種類、是否可能含個資或祕密、對應供應商。最後依風險排序，並針對最高風險的三項各提一個最小改動建議（移除、遮蔽或改本地），只提建議不要實作。若你不確定某處送出什麼，請直接說不確定，不要猜。
