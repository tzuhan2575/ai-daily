Anthropic 在 Nasdaq 掛牌（代號 ANT）：承銷價 83 美元、首筆成交 111.5 美元、收盤 97.17 美元；上市前宣布拿 5% 股份成立公益基金

Anthropic 官方定價公告與《Investing in the public benefit》（皆已讀全文）＋StockTitan 首日即時報導（已讀）＋Latent Space AINews＋HN 討論（781 分、1,462 則留言，讀了前 14 則頂層留言）；Reuters 原文擋爬蟲（401）只看到標題・11/18–11/19

Anthropic 官方公告：首次公開發行（IPO）定價每股 83 美元，共 9.8 億股 A 類普通股，其中 9.56 億股由公司自己賣、約 2,365 萬股由既有股東賣，承銷商另有 30 天內加買 1.47 億股的選擇權；Latent Space 換算總額約 813 億美元。依 StockTitan 的即時報導，11/19 美東 11:48 才在 Nasdaq 開出第一筆，成交價 111.5 美元（比承銷價高 34.3%），一分鐘後衝到當日最高 114.99 美元，之後一路回落，收在 97.17 美元（仍比承銷價高 17.1%），當天約成交 8.3 億股。HN 標題寫『市值 2 兆美元』，但這是 Reuters 用『完全稀釋』口徑算的；HN 有留言者用 Nasdaq 公布的流通股數（約 130.9 億股）乘 98 美元，算出約 1.28 兆。上市前一刻，Anthropic 另外宣布成立『Anthropic 公益基金』：經股東同意後先投入 5% 股份，公司價值每比基準多漲 50%，董事會可再加 2%。

白話：白話：做 Claude 的公司正式上市了，一般人從此可以在股市買它的股票。開盤很熱，比承銷價貴三成多，收盤時漲幅縮小到一成七。『市值多少兆』會因為算法不同差很多，看新聞時要留意用的是哪一種。另外它把一部分股份拿出來放進一個專做公益的基金。

我讀到什麼

讀了 Anthropic 官方的定價公告與公益基金公告全文；首日股價來自 StockTitan 的逐時更新（第三方財經網站，我沒有另外對照 Nasdaq 官方報價）；Reuters 那篇（HN 原文連結）回應 401 沒讀到，所以『2 兆美元』只能確定是它的標題用語。S-1 與最終公開說明書（424B4）本身我沒讀。

發行細節

官方公告：每股 83 美元，9.8 億股；公司不會拿到既有股東賣股的錢。SEC 在 11/18 宣告註冊生效，交易預定 11/20 交割。StockTitan 說 83 美元高於 11/17 第三次修正申報時的 70–78 美元區間；它也算出：以 83 美元乘上公開說明書中的約 132 億股（各類股合計），若一筆對七家科技公司、260 億美元的另行出售完成，整體價值約 1.1 兆美元。這些換算都出自 StockTitan，不是 Anthropic 說的。

為什麼開盤要等兩個多小時

新股第一天不是 9:30 一開市就成交，而是用 Nasdaq 的『IPO Cross』開盤競價，要等主辦券商通知準備好，才把所有買賣單撮合成一個開盤價。ANT 這次在 11:48 才開出，StockTitan 對照說 SpaceX 6/12 上市時是 11:46。另外要注意：在市場上買的人付的是成交價，不是承銷價 83 美元。

公益基金怎麼設計

官方說：基金是 Anthropic 全資擁有的 LLC（不是一般的 501(c)(3) 慈善機構），好處是能在不同捐贈形式間調整，例如大額捐給傳統非營利組織，或直接發放給特定族群；官方舉『AI 對勞動市場的衝擊』為例，並提到已承諾 2 億美元研究這件事。基金持有的股份不會用於遊說或政治捐獻。再加上共同創辦人創業時承諾捐出 80% 持股、約一半員工參加的股份捐贈配對計畫，官方估計約 20% 股份會用於公益。估值門檻與治理細節官方說『未來幾個月』才公布。

社群反應

HN 前排留言多半偏冷：有人說散戶是早期投資人的『出場流動性』，有人擔心像 1999 或 2007 年的過熱；有人質疑一季營收約 170 億美元的公司憑什麼值 2 兆；也有人恭喜員工。前排也有留言提醒『2 兆』是完全稀釋口徑，跟 Nasdaq 顯示的市值不同。昨天（第 24 期）提到的『MisAnthropic 聲明』爭議，在我讀到的前排留言裡沒有直接出現。

觀察點

① 上市後第一份季報何時出、會揭露哪些用量與毛利數字；② 公益基金的估值門檻與治理結構；③ 股價波動會不會影響員工留任與招募（推測）。

🧪 研究

OpenAI 公布內部『AI 加速研究』指標：2 到 4 小時的研究任務，agent 自己做完的比例從 23% 升到 46%；研究員每天中位數燒掉 2,400 美元的 agent 用量

OpenAI 研究報告《Research acceleration: The jagged frontier》（已讀主要內文文字，圖表、各節『View methods』展開內容沒看）・11/18

OpenAI 第二次公開『AI 幫 AI 做研究』的內部數據（第一次在 9 月）。官方說：3 月到 10 月，估計需要人類 2–4 小時的任務，agent 不需人介入就完成的比例從 23% 升到 46%；4–8 小時的任務從 13% 升到 35%。但很不平均：監看訓練是否出問題 79%、回答技術問題 72%，啟動訓練 35%、建立評測與強化學習環境 29%、寫推論與服務端程式只有 25%。用量面：以 API 牌價計，研究員每日 agent 用量中位數約 2,400 美元（9 月 1,500）、第 90 百分位約 23,000 美元（9 月 11,000）；每位研究員每天的『agent 工作日』（每 8 小時 agent 運作算 1 天）從 0.5 增加到 5.7。9 月時 agent 用量的 API 等值約是研究組織非股票薪酬的 2 倍，但內部使用只占研究算力的 2%。

白話：白話：OpenAI 統計自己的研究員怎麼用 AI。結論是：AI 已經能自己做完一半左右『人要花半天』的研究雜事，但有些工作（像寫推論伺服器的程式）它還是常常做不好，所以進步像鋸齒一樣，有高有低。
💡 為什麼重要這份報告等於一份『哪些工作交給 agent 比較穩』的參考表：監看、回答問題、分析比較穩；寫基礎設施程式、建環境比較不穩。你在做日報、個人助理時，也可以照這個分法決定哪些步驟放手、哪些一定要自己看。

為什麼要公開這個

OpenAI 主張 AI 實驗室應該被要求追蹤並公開『遞迴自我改進（RSI）』的指標，也就是 AI 加速開發下一代 AI 的程度。官方也特別寫：公開這些數據『不代表打算追求完整的 RSI』。這和 11/17（第 22 期）Scale AI 的 RSI Control Arena、11/18 GPT-6.2 首度在 AI 自我改進項目達 High 風險等級是同一條線。

研究員怎麼看

8 月底到 9 月初調查 101 位研究人員：假設三個月不能用比 GPT-5.2 更好的 coding agent，中位數願意拿團隊 40% 人力或 30% 算力去換回來。另一份 10 月底的小調查，28 人中有 27 人選擇『最新內部模型』而不是『一位中階研究工程師加上 2024 年的模型』。官方也提醒自評有準確性問題、抽樣方式是臨時的。

點子還是人想的

被問到 GPT-6 Astra 與 GPT-6.2 Astra 最重要的點子從哪來：後訓練與安全監控的研究員說點子都是人想的，模型負責實作；預訓練研究員在 6.2 Astra 這次則描述了跟 Codex 對話中發展點子，一位認為關鍵洞見是 Codex 指出的。官方把『研究品味』視為 RSI 可能的瓶頸。

安全與對齊的人力

官方說 1–9 月『安全與對齊』領域的人力投入增加最多（文件化的工作週增加 77%，報告另一處寫『幾乎翻倍』），轉折點在 7 月 Hugging Face 事件之後。這是用分類器把 Slack 貼文、PR、內部文件歸類估算的，不是正式組織編制。

觀察點

① 其他實驗室會不會跟進公開類似指標；② 推論服務、建評測環境這些低成功率項目何時追上；③ 『每人每天 2,400 美元』這種用量是否會反映到對外產品的定價與配額（推測）。

🏭 工具

OpenAI 的『效能工廠』：效能警報一響就由 Codex agent 找原因、另一個 agent 專門反駁、提修補 PR 給工程師審；三個多月調查 1,700 多件、找出 600 多件根因

OpenAI 工程部落格《How OpenAI's Performance Factory keeps ChatGPT fast》（已讀全文文字，流程圖與報告截圖沒看）・11/19；HN 只有 7 分、1 則留言，沒有討論可參考

OpenAI 公開內部系統 Performance Factory：用一組 Codex agent 自動處理 ChatGPT 的效能退化。第一條流程『Regression Workflow』在效能警報觸發時開一張任務，agent 找出退化何時開始、影響哪些請求、跟哪次部署或功能開關有關；接著由另一個 Codex 工作階段扮演『反方』試圖推翻這個診斷；通過後再寫修補並開 PR，由工程師審核合併；部署後再派 agent 確認效能回到基準。官方數字：三個多月追蹤 1,700 多次調查、找出 600 多個根因（平均每天 17 次）；人工抽查 100 個根因建議，70% 判為正確，30% 需要再修正或沒有完全建立因果。

白話：白話：以前網站變慢，要工程師自己翻監控圖、查日誌、讀程式找兇手。現在 OpenAI 讓 AI 先查、另一個 AI 挑毛病、再寫修正，人只負責最後審核要不要上線。
💡 為什麼重要這是一份很具體的『把 agent 放進正式流程』設計圖，跟你在做的日報自動化和個人 AI 助理同一類問題：任務狀態放哪、什麼時候叫人、怎麼評估改動有沒有變好。裡面的做法多半不需要 OpenAI 規模也能借用。

我讀到什麼

讀了全文文字；示意圖、範例任務報告的截圖沒看。數字都是 OpenAI 自己說的，沒有外部驗證；HN 上這篇幾乎沒人討論。

演進六階段

官方把團隊的變化分成：① 沒有 Codex，靠人和 30 多個自製效能工具；② Codex 當夥伴，人主導；③ 把調查流程寫成共用 skill『perf-forensics』，並用過去的事件做 eval 來調；④ 人變成『複製貼上的中繼站』，把警報貼給 Codex、再把結果貼回 Slack；⑤ 警報自動在雲端開 Codex 工作階段；⑥ 工廠化：任務有狀態、能在 agent 和人之間交接。

四個元件

① 任務服務：工程師用設定檔（config.toml）定義狀態與轉移、哪些步驟需要人，再用 Markdown 寫每個步驟給 agent 的指令；② 派工迴圈：定期檢查哪些任務可以往下走，就開一輪 Codex；③ 雲端 Codex：在內網環境跑，能用指標、日誌、追蹤、CPU 剖析等工具，以『服務身分』執行，方便限權與稽核；④ 訂閱：任務等人審 PR 或等部署時不必一直跑，事件來了（例如 PR 留言、CI 失敗）再喚醒。

反方審查與修補比找原因難

早期 agent 常停在第一個說得通的解釋。加入反方審查後，例如有一次 agent 把對話失敗歸因於找檔服務出錯，反方發現那個服務已經恢復、圖片請求卻還在失敗，就把調查重新打開。官方說『寫出正確修補比找到原因更難』：agent 的修補有時太複雜或帶來新問題，像『加快取』這種要權衡資料過期的決定仍需要熟悉服務的人。

怎麼評估 agent 本身

改 skill 或換模型可能讓某些案例變好、某些變差，所以分兩部分測：調查能力用過去的正式事故回測，每次開全新 agent、拿掉可能洩漏答案的資訊（不准讀記憶、事後報告、先前結果），事後還檢查對話紀錄有沒有『偷看答案』；摘要品質則用存下來的任務快照，由另一個評分者判斷不熟系統的工程師能否看懂。另外每天跑一個 agent 掃最近的失敗紀錄，把反覆出現的工具錯誤開成修理任務。

觀察點

① 官方說正在探索讓低風險修補不經人工直接上線；② 從被動等警報改成主動掃剖析資料找退化；③ 這套『任務狀態機＋派工＋事件喚醒』會不會變成 Codex 對外產品功能（推測）。

🛡️ 資安

工程師抱怨 Claude Code 的資安防護擋到『修自己系統的漏洞』：申請豁免要等數個工作天、交身分證件；最後改用歐洲託管的開放權重模型完成

結構化輸出：讓模型回『程式讀得懂』的 JSON，而不是一段話

為什麼今天學這個

第 5 週「Agent 安全與權限」四個主題昨天全部上完，週日週報才會正式切換；今天先預習第 6 週「把 AI 放進 App」的第一個主題「結構化輸出」。今天的新聞剛好示範為什麼需要它：OpenAI 的效能工廠把每個 agent 的發現寫進任務紀錄，讓下一個 agent 或工程師能接手——前提是輸出有固定格式。你的日報本身也是：每期都是一份要讓 build_site.py 讀得懂的 JSON；Tap Diary 若要讓 AI 幫忙分類日記，也需要固定欄位。本課的 API 用法出自 Claude 官方文件〈Structured outputs〉（我讀過全文相關段落），但我沒有實際呼叫 API（本環境沒有 API 金鑰）；本機驗證範例已用 jsonschema 4.26.0 實際執行。

是什麼

一般情況下，你請模型『用 JSON 回答』，它多半會照做，但偶爾會多一句話、少一個欄位、把數字寫成字串，程式一解析就壞掉。結構化輸出是 API 層的功能：你附上一份 JSON Schema（描述有哪些欄位、各是什麼型別、哪些必填），模型的回應就被限制成一定符合這份格式。Claude API 有兩種：『JSON 輸出』（在請求加 output_config.format）讓整個回答變成指定 JSON；『嚴格工具呼叫』（工具定義加 strict: true）保證工具名稱與參數符合定義。兩者可以分開用，也可以一起用。

為什麼需要

只靠提示詞時，你得寫一堆防呆：解析失敗就重試、缺欄位就補預設值、型別錯就轉換。官方文件列出的常見問題是：JSON 語法錯誤、缺少必填欄位、型別不一致、違反 schema 需要重試。結構化輸出用『受限解碼』從源頭解決：模型產生每個 token 時，不符合 schema 的選項直接被排除，所以不是事後檢查，而是根本寫不出錯的格式。對 agent 流程來說，這代表一個步驟的輸出可以直接當下一個步驟的輸入，不用中間再找人或再找一個模型『修 JSON』。

怎麼運作

依官方文件：你提供 schema 後，API 會把它編譯成一套『文法』，用來限制取樣。第一次用某個 schema 時要多花一點時間編譯，之後快取 24 小時（從最後一次使用起算）；改 schema 結構會讓快取失效，只改 name 或 description 不會。API 也會自動加一段系統提示說明輸出格式，所以輸入 token 會稍微變多；而且改變 output_config.format 會讓那段對話的提示快取失效（回想第 1 週的 KV cache 與提示快取）。Python SDK 建議用 client.messages.parse()，把 Pydantic 類別傳給 output_format，SDK 會轉成 schema、送出、驗證，再把結果放在 parsed_output。

限制與陷阱（官方文件列出的）

① 每個 object 都要設 additionalProperties: false，所以模型只能回你列出的欄位；不知道有哪些鍵時，改用 [{key, value}] 陣列。② 不支援數值範圍（minimum、maximum）、字串長度（minLength、maxLength）、oneOf、遞迴 schema 等；用了會收到 400 錯誤（SDK 輔助函式能把部分限制轉換掉）。③ enum 的大小寫『不保證』，例如可能回『Use』而不是『use』，比對時要不分大小寫。④ 兩種情況仍可能不符合 schema：模型拒答（stop_reason 為 refusal，仍會計費）與被 max_tokens 截斷（stop_reason 為 max_tokens）。⑤ 必填欄位會排在選填欄位前面，順序重要就全部設必填。⑥ 複雜度上限：所有嚴格 schema 合計選填參數最多 24 個、用 anyOf 或型別陣列的參數最多 16 個、strict 工具最多 20 個。

實務上怎麼搭配

結構化輸出保證『格式』，不保證『內容對』：模型仍可能在 level 欄位填錯判斷、在數字欄位填一個編出來的數字。所以通常是兩層：API 層用結構化輸出確保程式讀得懂；你自己的程式再做內容檢查（例如數值範圍——因為 API 不支援 minimum／maximum，這要你自己驗）。另外別在 schema 裡放『請寫出完整推理過程』這種欄位，官方說可能觸發 reasoning_extraction 拒答，改成『簡短說明理由』。

動手做（勾選記錄進度）

範例檔案

# check_impact.py：用 JSON Schema 檢查日報的 impact 欄位（本環境實際執行過，jsonschema 4.26.0）
import json, sys
from jsonschema import Draft202012Validator

SCHEMA = {
    "type": "object",
    "properties": {
        "level": {"type": "string", "enum": ["use", "watch", "skip"]},
        "text": {"type": "string"},
        "action": {"type": "string"},
    },
    "required": ["level", "text", "action"],
    "additionalProperties": False,
}

def check(obj):
    # 官方文件提醒：enum 大小寫不保證，驗證前先轉小寫
    if isinstance(obj.get("level"), str):
        obj = {**obj, "level": obj["level"].lower()}
    v = Draft202012Validator(SCHEMA)
    return [e.message for e in v.iter_errors(obj)]

samples = [
    {"level": "watch", "text": "短期不必換", "action": ""},
    {"level": "Use", "text": "可以試", "action": "跑一次"},
    {"level": "maybe", "text": "不確定"},
    {"level": "skip", "text": "無關", "action": "", "note": "多的欄位"},
]
for s in samples:
    print(json.dumps(s, ensure_ascii=False), "->", check(s) or "OK")

# ---- 實際輸出 ----
# {"level": "watch", "text": "短期不必換", "action": ""} -> OK
# {"level": "Use", "text": "可以試", "action": "跑一次"} -> OK            ← 先轉小寫才過

📚 今日新名詞

IPO（首次公開發行）公司第一次把股票賣給一般大眾並在交易所掛牌，之後任何人都能在股市買賣。
承銷價 vs 成交價承銷價是 IPO 時配給申購者的價格；上市後在市場買到的是當下成交價，兩者可能差很多。
完全稀釋市值把選擇權、限制股等未來可能變成股票的全部算進去的市值，通常比只算流通股的市值大。
公益公司（PBC）Public Benefit Corporation，美國一種公司形式，章程要求兼顧特定公共利益，而不只為股東獲利。
RSI（遞迴自我改進）AI 幫忙開發更強的下一代 AI，下一代又加速再下一代的循環。
agent 工作日OpenAI 報告的指標：agent 每運作 8 小時算 1 個工作日，用來衡量 agent 實際做了多少『時間』的工作。
反方審查（adversarial review）另開一個 agent 專門嘗試推翻前一個 agent 的結論，用來抓『第一個說得通就停』的錯誤。
誤報（false positive）系統說『有』但其實沒有，例如把洋芋片袋判成槍。
校準（calibration）讓模型輸出的信心分數符合真實機率，例如說 90% 的情況真的約九成是對的。
VLA（視覺－語言－動作模型）看影像、讀指令，直接輸出機器人動作的模型。
世界模型預測『做了某個動作之後，世界會變成什麼樣』的模型，可用來規劃或訓練。
結構化輸出（structured outputs）要求模型的回應一定符合指定的 JSON Schema，方便程式直接解析。
