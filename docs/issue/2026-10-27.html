Anthropic 向美國證管會提交 S-1，準備首次公開發行股票

Anthropic・10/26

Anthropic 官方公告說，已向美國證券交易委員會（SEC）提交 S-1 註冊聲明，擬首次公開發行 A 類普通股，計畫在那斯達克全球精選市場掛牌，代號「ANT」。股數與價格區間尚未決定；預備公開說明書出爐後，可向主承銷商高盛與摩根士丹利索取。

白話：S-1 是公司要上市時交給主管機關的申請文件，裡面會公開財務、風險與業務細節。「已提交」不等於「已上市」：註冊聲明還沒生效，所以現在不能買賣這些股票。
💡 為什麼重要你每天用的 Claude Code 與 API 背後是這家公司。上市會帶來公開財報與風險揭露，之後外界能更清楚看到它的營收結構與成本，對評估「長期要不要押注這個平台」有參考價值（推測）。

Anthropic 擴大 Cyber Verification Program：資安人員可申請三級權限

Anthropic・10/6

官方公告（10 月 6 日發布，本期補報）把先前的 Project Glasswing 與 Cyber Verification Program 合併成單一計畫，分三級：Defense（防禦，如事件應變、惡意程式逆向、漏洞分析，數日內回覆）、Red Team（再加授權滲透測試，僅限組織，審核數週）、Specialized（阻擋最少，限少數驗證過的組織，與美國政府合作深度審查）。一般公開模型仍保留保守的資安防護，會擋掉多數資安工作。

白話：AI 模型寫攻擊程式和寫防禦程式很難區分，所以預設會擋。這個計畫是讓通過身分審查的資安人員，拿到擋比較少的版本。
💡 為什麼重要如果你用 AI 審自己的程式碼或處理安全警報，一般模型仍可用；只有需要逆向、攻擊模擬這類工作才需要申請。這也示範了廠商怎麼把『危險能力』分級開放。
🎯 對你的影響　👀 值得追蹤
你目前做日記 App 與個人工具，一般公開模型的資安能力（審碼、修已知漏洞、分流警報）就夠用，不需要申請。（推測）

📖 展開完整解析（6 段）

三級權限

Defense：公司、非營利、大學、政府資安團隊、關鍵基礎設施營運者、小型資安公司、開源維護者，以及有漏洞通報紀錄的個人研究者。Red Team：僅組織（內部紅隊、政府紅隊、滲透測試公司），審核期間先給 Defense。Specialized：限制最少，對象是能影響生命或市場的系統測試，例如飛航、電網、電信、銀行間轉帳。

仍然會擋的事

官方說即使 Red Team 也保留即時阻擋，針對可能造成實體傷害或大規模中斷的行為，例如部署勒索軟體、破壞實體系統。

官方測試數字

官方用 Claude Opus 5.5 在 CyScenarioBench（多階段網路攻擊情境）測試，10 個題目各 5 次共 50 次：無權限時第一個提示就全被擋；Defense 有 46 次在某處被擋、4 次成功；Red Team 沒有被擋，完成 34 次。這些都是官方自己的測試，我沒有看到第三方驗證。

漏洞發現數字

官方稱 Glasswing 夥伴在 4 到 7 月找到至少 12.9 萬個經驗證的漏洞，自家掃描開源專案另有 5,500 個（4 到 10 月）；其中超過 3.3 萬個為高或嚴重。官方也說這是下限，只有部分夥伴揭露修補數字，樣本是 33 份夥伴報告。

資料條件

加入的組織必須允許資料保留，讓官方監控濫用；預計秋季稍後推出的 Enterprise Frontier Safeguards 可讓組織把資料放在自己控制的雲端。零資料保留（ZDR）客戶在那之前，限特定模型可用。

怎麼申請

透過 CVP 入口網站，需提供各級要求的安全控管證明；管理員要把計畫指派到特定工作區。公開模型被誤擋可以提交誤報或申訴。

上下文視窗：模型的「工作記憶」到底裝了什麼

為什麼今天學這個

課程第 1 週接著上下文視窗。你的 Claude Code 對話越長越慢、越貴、越容易忘，原因都在這裡。

是什麼

官方文件的說法：上下文視窗是模型生成回應時能參考的所有文字，包含它自己的回應。它像「工作記憶」，不是訓練時看過的大量資料。

裡面裝什麼

文件說，請求中的一切都算：系統提示、messages 裡每一則訊息（含工具結果、圖片、文件）、工具定義；模型輸出（包括思考內容）也算。每次回應的 usage 欄位會回報用量；使用提示快取時，輸入會分成 input_tokens、cache_read_input_tokens、cache_creation_input_tokens，三者都算進視窗。

每一輪都累積

API 是無狀態的：每一輪的輸入 = 之前全部對話歷史 + 這次的新訊息；模型的回答又會變成下一輪的輸入。所以對話越長，每一輪要處理的 token 越多。

越大不一定越好

文件明說：token 越多，準確度與召回會下降，稱為 context rot，所以「放進什麼」和「有多少空間」一樣重要。文件列出的多款新模型視窗是 1M token，單次輸出最多 128k。

滿了會怎樣

若輸入本身就超過視窗，API 回 400 invalid_request_error（prompt is too long）。Claude 4.5 以後的模型，輸入加 max_tokens 超過視窗時仍接受請求，生成到上限會以 stop_reason: model_context_window_exceeded 停下。

怎麼管理

文件建議長對話用伺服器端壓縮（compaction，beta），或用 context editing 清掉舊的工具結果。快取只改變計價，不會讓這些 token 不佔視窗。我沒有實際呼叫 API 驗證這些行為，以上取自官方文件。

動手做（勾選記錄進度）

貼給 Claude Code 的指令

請依 Anthropic 官方文件「Context windows」，用白話向我解釋：1) 上下文視窗包含哪些東西 2) 為什麼對話越長每一輪越貴 3) context rot 是什麼 4) 我在 Claude Code 裡有哪些做法能降低上下文占用（例如開新對話、/compact、減少不必要的工具與長檔案）。請標明哪些是官方文件說的、哪些是你的推測。
