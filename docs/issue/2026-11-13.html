💧 模型發布

Gemini 4 Hydrogen 上線：主打快速執行，官方說智慧指數超過 Argon，輸入 1.5 美元、輸出 7.5 美元／百萬 token

Google 官方部落格（已讀全文文字，圖表未看）・11/12；Latent Space AINews・11/12；HN 討論（只看標題與分數 413 分、278 則留言）

Google 11/12 推出 Gemini 4 Hydrogen，定位是 Gemini 4 家族裡的『快速執行』模型，Carbon 與 Argon 負責深度推理，Hydrogen 負責寫程式、跑測試、驗證這類日常 agent 工作。官方說法：在 Artificial Analysis Intelligence Index 預設 high 思考等級拿 51 分，超過 Argon 的 50 分，最高的 xhigh 等級到 54 分；整個 100 萬 token 上下文統一定價，輸入每百萬 token 1.50 美元、輸出 7.50 美元；與 Gemini 3.8 Flash 比，high 等級完成任務快 2.5 倍、Terminal-Bench 4.1 從 18.2% 升到 57%、捏造陳述減少超過 5 倍。同日推出 Antigravity 的 Orchestrator，可在同一工作階段自動切換 Carbon 與 Hydrogen，官方說在 Terminal-Bench 4.0 上接近 Carbon 的成功率、平均少用 24% 額度、快 19%。今天起開放於 AI Studio、Gemini API、Gemini App、Google 搜尋、企業版，Antigravity 限付費 AI Pro／Ultra。以上數字都是 Google 自己公布，我沒看到第三方完整驗證。

白話：白話：Google 把模型分成『想很久的大腦』（Carbon、Argon）和『手腳快的執行者』（Hydrogen）。Hydrogen 便宜、快，大部分寫程式、整理資料的雜事交給它；遇到真正難的設計問題再叫大模型。Orchestrator 就是自動幫你決定這一步該叫誰。
💡 為什麼重要你平常用 Claude Code，Hydrogen 是同價位帶的直接競品；『大模型規劃、小模型執行』的分工也是你做個人助理時可以借用的架構。它在 Gemini App 與 Google 搜尋的預設體驗也會跟著變。
🎯 對你的影響　👀 值得追蹤
（推測）若你在個人助理或日報流程裡需要便宜又夠聰明的執行模型，Hydrogen 是可比較的選項；但你主力是 Claude Code，暫時不必換。
▶ 等 Artificial Analysis 或 Vals 公布 Hydrogen 的獨立數字後，拿你常用的一個小任務（例如整理一篇文章成 JSON）在 AI Studio 和你現用模型各跑 3 次，比較正確率與耗時。

四種思考等級

low、medium、high（預設）與新增的 xhigh。官方說各等級在品質、延遲、成本上是平滑遞增，『只為任務需要的推理深度付費』。這和 Claude 的 effort 設定概念類似。

官方列出的評測

HLE-Diamond 58.8%（官方說同級領先）、Vals Tax Agent Bench 52.3%（第一）、Vals Legal Research Bench 55.8%（並列第一）、Multimodal Knowledge Agent 53.4%、Agents' Last Exam v1.1 71.6%、Agent Arena 第 5 名。這些數字都來自 Google 文章；MKA 是 Google 自己同天推出的新基準，自出題自評要打折看。

寫程式的特性

官方強調『外科手術式』修改、不亂動無關檔案，以及會平行批次呼叫讀檔與搜尋工具。合作夥伴在早期測試中，相較 3.8 Flash 快 2 到 2.8 倍、token 少 12% 到 23%（合作夥伴回報，非公開評測）。

安全宣稱

官方說 agent 任務中『越權』最多降 81%、偷工減料等不對齊行為降 12 倍、被擋時繞過權限邊界的機率最多降一半、內部誠實度評測 96.7%；Gray Swan 間接提示注入基準上韌性提升 2.3 倍以上。全部是官方或其合作評測的說法。

觀察點

前幾天社群對 Carbon 的抱怨集中在延遲（Latent Space 轉述 Theo 量到首 token 約 11 秒）；Hydrogen 主打快，實際首 token 延遲與長任務表現要等第三方量測。

🧮 工具

同一個 GitHub 任務：CLI 用 1,421 token、Skill 3,315、預設 GitHub MCP 伺服器 59,417

OpenRouter 官方部落格（已讀全文）・11/11；TLDR AI・11/12

OpenRouter 用同一題（查 cli/cli 最新版本與最近三個 bug 標籤的 issue）比較三種給 agent 能力的方式。在 Claude Sonnet 5.5 上三種都答對，但輸入 token 差很多：gh CLI 1,421、gh 的 Skill 3,315、GitHub MCP 伺服器只開 2 個工具 23,228、預設 46 個工具 59,417、全部 91 個工具 101,351。換算每 1,000 次任務，預設 MCP 約 127 美元、CLI 約 7.5 美元。GitHub MCP 伺服器預設 46 個工具的定義本身每次請求就多出 19,436 token（Claude 計數）；單一個 get_latest_release 結果有 42,182 字元，約 20,400 token，比 46 個工具定義還多。把工具結果截到 4,000 字元後，2 個工具的 MCP 降到 5,357 token。每組跑 3 次取中位數，實驗日期 10/20，只測一個伺服器一個任務。

白話：白話：每接一個 MCP 工具，它的說明書每次對話都要整份塞給模型看，你就得付錢。CLI 只要告訴模型『你有 gh 指令可用』；Skill 平常只放一行簡介，真的要用時才讀完整說明。另外，工具回傳一大包 JSON 也會一直留在上下文裡被重複計費。
💡 為什麼重要你每天用 Claude Code、又有自己的 skills，這直接關係到你的 token 帳單和上下文被吃掉多少。這篇給了可照做的原則：能用 CLI 就用 CLI，自己的 CLI 配一個 Skill，MCP 要縮小工具範圍並裁切回傳欄位。
🎯 對你的影響　🔧 可立即用
你的 Claude Code 若掛了多個 MCP 伺服器，可能每次請求都在付上萬 token 的工具說明費；你的 skills 寫法本來就是比較省的那種。
▶ 在 Claude Code 裡輸入 /context 看目前上下文各部分占多少，再在終端機跑 claude mcp list，把沒在用的伺服器用 claude mcp remove <名稱> 移除。（今日一課有完整步驟）

三種方式的差別

MCP：每次請求都送每個工具的名稱、描述、JSON schema。CLI：只送一個 shell 工具加一句『gh 已安裝』，靠模型本來就會用。Skill：平常只送一行索引，需要時才讀 SKILL.md，讀過後內容留在對話中，所以比純 CLI 貴一點。

同樣的工具，不同模型算法不同

同 46 個工具：Haiku 5.5 多 19,436 token、GPT-6 Luna 多 8,903、Gemini 3.8 Flash 經 Vertex 多 8,525，但經 AI Studio 是 13,010。作者建議用『有工具和沒工具各送一次、相減 prompt_tokens』的方式在你自己的模型上量，不要用本地 tokenizer 估。

工具結果才是隱形大戶

release 物件 87% 在描述 22 個下載檔，模型只需要版本號和日期。用 gh release view --json tagName,publishedAt 只回兩個欄位。list_issues 指定 fields 參數後，結果從 8,336 字元降到 714。GPT-6 Luna 在 6 次中有 4 次主動要了 100 筆完整 issue，拿回 281,963 字元。

Tool Search 不是萬靈丹

把 46 個工具設成延後載入後，搜尋前的成本在 Claude 上剩 578 token。整個任務下 Sonnet 5.5 從 59,417 降到 30,334，但 Haiku 5.5 反而從 99,319 升到 154,623，因為它反覆用錯參數型別重試。作者建議迴圈要設上限。

作者的建議

有知名 CLI 且能跑指令就用 CLI；自己的 CLI 或模型用不穩的 CLI，加一個 Skill；沒 shell 或需要伺服器的認證權限才用 MCP，並縮小工具範圍；任何 MCP 路線都要裁切結果。提示快取只降低單價、不減少佔用的上下文。

限制

這是 OpenRouter 自己的測試，而 Tool Search 是他們的產品功能，有利益關係；只測一個伺服器、一個任務、每組 3 次。結論方向合理，但數字不能直接套到你的情境。

🦾 研究

Runway 以 Apache 2.0 開放 Praxis-1 權重：27B 的『世界動作模型』，RoboLab-120 成功率 46.2%

Runway 官方公告（已讀全文）・11/11；TLDR AI・11/12；Latent Space AINews・11/12

Runway 11/11 宣布 Praxis-1 開放權重，授權 Apache 2.0、可商用，含推論與微調程式碼，支援完整微調與 LoRA。它是 27B 參數的混合專家（MoE）擴散 Transformer，同時預測未來影片與機器人動作，9 月首次發表。官方數字：在 NVIDIA 的 RoboLab-120 排行榜 1,200 回合成功率 46.2%，高於 FLUX 3 Action 42.9%、Cosmos3 Nano 36.8%、π0.5 28.0%；在訓練資料沒出現過的 Google RT-1 機器人上微調後，SimplerEnv 成功率 80.0%，原本 RT-1 策略為 52.4%。可在 GitHub、Hugging Face（原生支援 LeRobot）、vLLM-Omni 取得，官方說從 H100、B200 到 RTX 5090、RTX PRO 6000 與機器人端的 Jetson Thor 都能跑。Latent Space 另轉述 NVIDIA 已發布 NVFP4 版本檢查點。

白話：白話：一般機器人模型是『看畫面 → 輸出動作』。Praxis-1 多做一件事：同時想像『接下來畫面會變成怎樣』。因為它先看了大量網路影片，學到物體怎麼動，所以換到新的機器手臂時，只要少量微調就能用。
💡 為什麼重要你有機器人感知背景，這是少數規模大、權重開放、又能商用的機器人基礎模型，還接上 LeRobot 生態；拿來當 baseline 或在自己的手臂上 LoRA 微調都可行。
🎯 對你的影響　👀 值得追蹤
（推測）若你之後回到機器人或手臂專案，這是值得列入的開放 baseline；目前你的主要專案（Tap Diary、日報、個人助理）用不到。
▶ 把 Praxis-1 的 Hugging Face 模型卡加進筆記庫的『機器人基礎模型』頁，記下授權、參數量與硬體需求，等有人公布實機重現再評估。

我讀到什麼

讀了 Runway 官方公告全文；示範影片沒看；技術報告與 GitHub、Hugging Face 模型卡沒讀，所以硬體需求（例如需要多少 VRAM）我無法確認。

什麼是世界動作模型

把『世界模型』（預測環境下一步長怎樣）和『策略』（決定要做什麼動作）合在同一個模型裡。Runway 宣稱他們的研究顯示，網路影片當預訓練資料，對策略表現的幫助和遙控操作錄下的機器人影片相當，所以瓶頸變成『能吃多少一般影片』。這是官方說法，我沒讀到原始研究。

分數怎麼看

RoboLab-120 由 NVIDIA 維護、Runway 與 NVIDIA 同屬 Cosmos Coalition，兩者有合作關係。46.2% 是排行榜第一，但絕對值仍代表一半以上的回合失敗。RT-1 微調結果是在模擬環境 SimplerEnv，不是實機。

上線合作夥伴

Noble Machines（腿式人形）、Standard Bots（六軸工業手臂）、Ultra（雙臂倉儲機器人）已在自己的硬體上跑。Latent Space 轉述 Runway 宣稱比 GPT-6 Astra 驅動同一手臂快 15.6 倍、每任務成本低 51 倍，我沒讀到原始比較方法。

觀察點

27B 在 Jetson Thor 上的實際延遲與控制頻率、LoRA 微調需要多少示範資料，以及社群在實機上的重現結果。

🧱 資安

Perplexity 讓 12 個模型試著逃出自家 agent 沙箱：沒有模型突破 VM 隔離，但有模型用 DNS 偽造繞過網路限制

Perplexity 官方部落格（已讀前半與網路繞過段落開頭，後段未讀完）・11/11；TLDR AI・11/12

Perplexity 的 agent 沙箱 SPACE 用 Firecracker microVM 執行 agent，假設 agent 可能是惡意的並已取得 VM 內 root。第一部分測了 9 個模型，第二部分再加入 Claude Mythos 5.1、Claude Opus 5.5、GPT-6 Astra，共 12 個。結果：沒有任何一次成功從 VM 逃到主機；但在『可連部分網域（PyPI、Ubuntu 鏡像等）』的設定下，數個模型用 DNS 偽造與共用 IP 的手法連到被封鎖的網址，相關漏洞已修補。第一部分時，Perplexity 也在 10 個第三方沙箱平台中的 8 個發現類似漏洞並已通報。新發現：用 CTF『找旗子』的出題方式時，模型大多在 VM 裡搜憑證，很少真的攻擊虛擬化層；改用聚焦虛擬化層的提示後，相關投入平均增加約 60 個百分點，仍無人逃脫。

白話：白話：Perplexity 把 AI agent 關在一台虛擬電腦裡，直接叫它『想辦法逃出去』。結果沒有一個逃出虛擬機，但有幾個鑽了網路規則的漏洞，連到不該連的網站。這提醒大家：沙箱的『網路白名單』往往比虛擬機本身更容易破。
💡 為什麼重要你讓 Claude Code 等 agent 跑指令、裝套件時，常會開『只允許 PyPI 等網域』的網路設定；這篇顯示白名單本身可能被繞過，而且多數第三方沙箱都有類似問題。

AWS 開源 AWS Emulator，在本機、開發伺服器或 CI 裡模擬 AWS API，不需要 AWS 帳號、請求不會送到 AWS、本身不收費。兩種模式：伺服器模式（Linux 裝 RPM／Debian 套件後執行 aws-emulator；Windows／macOS 用 Docker），設好環境變數讓 AWS CLI 或 SDK 指向它；嵌入模式（Rust 測試專用）把模擬器編進測試程式，每個測試一個獨立實例。也提供 coding agent 用的 skill，安裝指令是 aws agent-toolkit add-skill --skill-name aws-emulator --region us-east-1，需要 AWS CLI 2.35.0 以上。從原始碼建置需要至少 100 GB 磁碟空間；啟動後在 127.0.0.1:9297 提供 HTTPS（自簽憑證）。遙測預設開啟，可用 --telemetry off 或 EMULATOR_TELEMETRY=off 關閉。授權為 CC0 1.0（vendor/ 目錄為 Apache 2.0），不接受 PR。

工具也吃上下文：MCP、CLI、Skill 各花多少 token，怎麼在 Claude Code 裡瘦身

為什麼今天學這個

今天 OpenRouter 的實測顯示，同一個 GitHub 任務，預設 MCP 伺服器吃的輸入 token 是 CLI 的 42 倍。你每天用 Claude Code、又有自己的 skills，這和你的日常工具直接相關，所以插隊；它也複習第 1 週『上下文視窗』與第 2 週『MCP、Agent Skills』。第 4 週已結案。實驗數字來自 OpenRouter 文章；Claude Code 指令中 claude mcp list／remove 我在此環境確認過 --help 有列出，但 /context 與實際瘦身流程我沒有實際執行。

是什麼

模型每次回答前，都要重新讀一遍『這次請求的全部輸入』：系統提示、對話紀錄、工具定義、工具回傳結果。給 agent 能力有三種常見方式：MCP 伺服器（把每個工具的名稱、說明、參數格式全部塞進去）、CLI（只告訴模型可以跑某個指令）、Skill（平常只放一行簡介，要用時才讀完整說明）。三者能力差不多，佔的空間差很多。

為什麼重要

第一是錢：輸入 token 要計費，工具定義每一輪都會重送。OpenRouter 在 Sonnet 5.5 上量到預設 GitHub MCP 每 1,000 次任務約 127 美元，CLI 約 7.5 美元。第二是品質：上下文視窗是有限的，被工具說明和大包 JSON 佔掉，留給你的程式碼與對話的空間就少了。提示快取能讓重複部分變便宜，但不會讓它們少占空間。

怎麼運作：兩個大戶

第一個大戶是工具定義：GitHub MCP 預設 46 個工具，每次請求多 19,436 token（Claude 計數）；工具越多越貴，而且同樣的工具在不同模型、甚至不同供應商的計數都不同。第二個大戶是工具結果：一次 get_latest_release 回傳 4 萬多字元，約 2 萬 token，而且會留在對話裡，之後每輪都重送。CLI 能用 --json 指定欄位，只回需要的東西。

怎麼選

OpenRouter 的建議：有知名 CLI 且 agent 能跑指令，就用 CLI；是你自己寫的 CLI，或模型用得不穩，就加一個 Skill 教它；沒有 shell、或需要伺服器提供的認證權限，才用 MCP，而且只開需要的工具、裁切回傳欄位；工具很多時考慮延後載入（Tool Search），但它在某些模型上反而更貴，要量過再說。

怎麼量自己的

最可靠的方法是『有工具和沒工具各送一次相同請求，看回傳的 prompt_tokens 差多少』，因為各家在計數前會把工具定義轉成自己的格式，本地 tokenizer 算不準。在 Claude Code 裡，/context 指令可以看目前上下文的組成；claude mcp list 列出已設定的 MCP 伺服器。

動手做（勾選記錄進度）

範例檔案

例：OpenRouter 用同一題在 Sonnet 5.5 上量到：gh CLI 1,421 token、gh Skill 3,315、GitHub MCP 只開 2 個工具 23,228、預設 46 個工具 59,417；把 MCP 工具結果截到 4,000 字元後降到 5,357。
