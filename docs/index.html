Agent Skills 開放標準捐贈給 Linux Foundation 旗下的 Agentic AI Foundation

Anthropic・10/22

官方文章（10 月 22 日）說，Anthropic 把 Agent Skills 這個開放標準捐贈給 Agentic AI Foundation（AAIF，隸屬 Linux Foundation）。捐贈內容包括標準本身、名稱與 logo、GitHub 組織與 agentskills.io 網域。官方稱自 2025 年 12 月發布標準以來，已有 70 多個 agent 平台整合，文中點名 ChatGPT、Cursor、GitHub Copilot、VS Code；已發布的 skills 約 100 萬個，安裝次數接近 2.8 億次（皆為官方數字，未見第三方驗證）。

白話：白話：Skill 就是一個資料夾，裡面放一份 SKILL.md，教 AI 代理人怎麼做某件事。現在這份格式從「一家公司的規格」變成「中立基金會管的公共規格」，像 USB 規格交給標準組織而不是留在單一廠商手上。
💡 為什麼重要你日常用 Claude Code 也有自己的 skills。標準中立化意味著你寫的 SKILL.md 更可能在別的工具上也能用，投資在 skills 上比較不會被綁死（推測）。
🎯 對你的影響　👀 值得追蹤
你自己有 skills，標準轉向中立基金會對你是正面訊號；短期不需改動任何東西，但之後若出現版本化或安全指引，可能需要對照你的 skills 格式（推測）。
▶ 先讀 agentskills.io 的規格頁，對照你現有一個 skill 的 SKILL.md 看有無落差。
📖 展開完整解析（6 段）

發生什麼

Anthropic 與 Block、OpenAI 去年共同創立 AAIF，並曾把 Model Context Protocol（MCP）捐給同一個基金會，這次是第二個捐出的標準。官方說不加入 AAIF 也可以使用或貢獻此標準。

Skill 是什麼

依官方描述，一個 skill 是一個資料夾，內含 SKILL.md，教 agent 特定任務或領域知識，也可帶腳本與參考資料。官方說起因是開發 Claude Code 時發現模型能做一般知識工作，卻常缺少真實商業任務所需的程序性知識。

治理方式

維護者由 Anthropic、Google、OpenAI 等公司的工程師以個人身分擔任，Lead Maintainers 為 David Soria Parra 與 Mahesh Murag（文章所列）。官方承諾保持開放、社群驅動、廠商中立。

路線圖

官方提出三項：版本化發布、正式的提案流程、針對撰寫與安裝 skills 者的安全指引。最後一項值得留意，因為 skills 可帶腳本，安裝別人的 skill 等同執行別人的程式碼（這是我的推論，文章只說會有安全指引）。

參與方式

規格在 agentskills.io，討論在 GitHub 的 agentskills/agentskills，規格變更提案回饋可透過專案 Discord。

我沒讀到的部分

文章沒有欄位定義或格式版本等規格細節，我也沒讀規格本文、社群反應或第三方評論；採用數字全是官方說法。

Anthropic 與美國 GSA 擴大合作：各級政府採購 Claude 可享 40% 折扣

Anthropic・10/27

官方文章（10 月 27 日）說，透過與美國總務署（GSA）的新協議，Claude Enterprise、Claude for Government 與 Claude API 對聯邦、州、地方、部落與領地政府提供 40% 折扣，公司估計可節省約 10 億美元，機構沒有最低消費承諾。官方稱目前約 500 個美國各級政府機構使用 Claude，自 2 月以來 Claude for Government 每週活躍用戶約成長 8 倍。

白話：白話：政府單位買這家公司的 AI 服務，現在透過 GSA 的採購管道能拿到統一折扣，而且用多少付多少。
💡 為什麼重要這是 AI 公司如何進入公部門的做法樣本，也能看出供應商如何用合規認證當競爭條件；與你的個人專案無直接關係。
🎯 對你的影響　💤 略知即可
屬於公部門採購與商業消息，與你目前的專案無直接關係。
📖 展開完整解析（6 段）

折扣範圍

官方說這是首次折扣涵蓋所有產品形式，包括機構現在直接向公司採購，以及未來幾個月透過雲端供應商採購；機構可經 GSA 的 Multiple Award Schedule 以 OneGov 折扣價購買。文章未列具體單價，10 億美元是公司自己的估計。

合規與認證

文章提到 Claude for Government 在 FedRAMP High 等級下提供接近商用版的功能；Amazon Bedrock 與 Google Vertex AI 上的 Claude 已有 FedRAMP High 授權，部分模型在 AWS GovCloud 獲 DoD IL4／IL5 授權；Claude Enterprise 正申請 FedRAMP Moderate，尚未取得。

官方案例（未獨立驗證）

猶他州 34 名開發者、10 個機構的四週試點：80% 在 30 分鐘內建好可用環境，71% 說節省 20 小時以上。某州 IT 開發者兩天遷移近 900 個 API 方法（原規劃一個月）。某州 IT 主管記錄 12 個舊程式庫、467 張資料表並標出 27 項風險。這些案例多未具名機構。

資安案例

文章稱某聯邦資安團隊用 Claude Mythos 在約兩天內偵測並修補一個可能導致關鍵生產系統被接管的漏洞，前一個月的人工滲透測試未發現；另有州 CIO 稱勒索軟體事件回應時間 8 分鐘（通常 2 到 3 天）。同樣是單方面敘述，我沒有交叉查證。

後續計畫

公司說將推出協助機構導入的專門計畫，並在未來幾週把私營客戶的最佳實務帶給公共部門夥伴。

MCP：讓模型用標準方式呼叫外部工具

為什麼今天學這個

課程進入第 2 週「Agent 與工具使用」。今天新聞提到 Agent Skills 與 MCP 同被捐給同一個基金會，兩者常被搞混，所以今天先講 MCP；Skills 已在 10/26 上過。以下為一般原理，非來自今日原文。

是什麼

模型本身只會輸出文字。要讓它查資料、讀檔案、操作系統，就要給它「工具」：模型輸出一段結構化的呼叫請求，由外部程式真的執行，再把結果餵回模型。MCP（Model Context Protocol）是一份標準，規定工具提供方（server）與使用工具的應用（client，例如 Claude Code）之間怎麼溝通。

為什麼要標準

沒有標準時，每個應用都要為每個服務各寫一套接法。有標準後，服務只要做一次 MCP server，支援 MCP 的應用都能接，像是共用插座規格。今日文章說 MCP 已捐給 Agentic AI Foundation。

和 Skills 的差別（我的理解）

Skills 是教模型「怎麼做」的說明與腳本資料夾；MCP 是讓模型「接到」外部系統的連線協定。一個管知識與流程，一個管連線與能力。這是概念上的區分，細節以官方文件為準。

怎麼運作（概念）

client 啟動或連上 server，先問它有哪些工具與參數描述；模型看到這些描述後決定要不要呼叫；client 執行並把結果回傳。工具描述本身會佔用上下文（第 1 週學過），接太多工具會變貴、變慢。

安全提醒

接上的 server 能做什麼就等於模型能做什麼，所以只接信任的來源、最小權限。這是一般原則。

動手做（勾選記錄進度）

貼給 Claude Code 的指令

請先閱讀 Claude Code 官方文件中關於 MCP 的說明，然後用繁體中文告訴我：1) 新增一個 MCP server 的步驟；2) 權限如何控管；3) 我的筆記庫資料夾適合用哪種只讀方式接上。不確定的地方請明說，不要編造指令。
來源：一般原理（未實際執行任何 MCP 工具）；Anthropic 10/22 官方文章（僅用於 MCP 已捐贈的事實）
