🗓 2026-W45・11/2–11/8

本週我該做什麼

1. 用「改需求」自己驗證模型，不只看榜單

MaxxBench 顯示榜單分數接近時，差異可能是猜測測試；用自己的任務檢查才知道新模型是否真的比舊的好。

▶ 挑 3 個 Tap Diary 或日報網站的小任務，各寫一個改過需求的版本，兩個模型各跑一次，記錄通過與否。步驟見 11/8 的課。

2. 檢查是否有跑 PHP 的主機並確認版本

PHP2Shell 說明 AI 協助下，舊的記憶體錯誤兩週內就被串成可執行任意程式碼的漏洞；你的 Flutter App 與靜態日報網站不受影響，但身邊若有 PHP 站台（含 WordPress）要留意。

▶ 在主機執行 `php -v` 看版本，到 PHP 官方安全公告頁確認該版本是否已有對應修補，有就升級。沒有 PHP 主機就略過。

3. 盤點 Git 連線金鑰與 API 測試工具的設定

GitBook 事件提到 Git Sync 密鑰可能外洩，Postman 傳聞（未驗證）則提到 AI 外掛可能外送請求內容；兩者共通的風險是金鑰放在別人能讀到的地方。

▶ 到 GitHub 的 Settings → Deploy keys 與 Personal access tokens 檢視是否有用不到的金鑰並移除；若用 Postman，檢查 AI 相關功能是否啟用，測試用金鑰改成可隨時作廢的低權限金鑰。

4. 確認常用 AI 服務的資料控制設定，並補上 Tap Diary 隱私說明

個人版 Gemini 預設用聊天紀錄訓練的討論，與 macOS 推論個人資料的報導，都提醒「推論或保留的資料要講清楚」；Tap Diary 是日記類產品，這是你自己要回答的問題。

▶ 打開常用 AI 服務的資料控制頁，確認訓練選項與保留期限；在 Tap Diary 隱私說明補上三句話：哪些資料存在本機、是否有推論資料、如何刪除。

本週脈絡

  • 資安是連續幾天的主線：11/3 WorkOS、11/4 GitBook 都通報疑似 AI 輔助攻擊，11/5 的 PHP2Shell 顯示 AI 讓舊 bug 更快被串成可利用漏洞，11/6 則有 OpenAI 的資安專用模型 GPT-6 Cyber。這些多半來自摘要或轉述，細節與影響範圍請以官方公告為準。
  • 與你的電腦視覺／機器人背景相關的有 NVIDIA Cosmos 3 開放權重世界模擬模型（11/6、11/8）、DreamX、Ai2 的 ToyBlocks；多為官方說法或摘要等級，目前都只列為觀察。
  • 隱私議題出現兩則：個人版 Gemini 預設用聊天紀錄訓練（HN 討論，11/5）與 macOS 本機建立個人知識圖譜（11/8）。對做日記類 App 的你，可當作隱私設計的對照。
  • 學習方面，第 2 週「Agent 與工具使用」（tool use、多代理人）收尾，並把第 3 週「評測與選型」的三個主題（pass@k 與 benchmark、延遲、開放權重 vs 閉源）加上自己做小型 eval 全部上完，另預習了第 4 週的硬體需求估算。
🗓 2026-W44・10/26–11/1

本週我該做什麼

1. 把常重複貼給 AI 的流程做成自己的 skill

Agent Skills 已是跨工具的開放標準，寫一次可在多個編輯器與代理人使用，不必綁定單一廠商。

▶ 挑一段你最近重複貼給 AI 的流程，建一個資料夾，裡面放 SKILL.md（開頭 YAML frontmatter，之後用 Markdown 寫操作說明），放進 Claude Code 的 skills 目錄試用。步驟見 10/26 的課。

2. 對照 agentskills.io 規格與你現有的 SKILL.md

標準轉交中立基金會後，之後可能出現版本化或安全指引；先對照可以早點發現落差（推測）。

▶ 讀 agentskills.io 的規格頁，挑你現有的一個 skill，檢查 frontmatter 欄位與目錄結構有沒有和規格不一致的地方。

3. 請 Claude Code 為 Tap Diary 做一次資安審查

一般公開模型就能做審碼、找已知漏洞與分流警報，不需要申請 Cyber Verification Program；上 Google Play 前先檢查很划算。

▶ 在 Flutter 專案目錄請 Claude Code 檢查相依套件版本（例如 flutter pub outdated）與 Android 權限設定（AndroidManifest.xml），並列出建議修正清單。

4. 等 S-1 內容公開後讀風險因素章節（觀察項）

你的助理與 Tap Diary 若依賴該公司 API，風險因素章節會寫模型供應與安全政策對客戶的影響；目前不需要改任何東西。

▶ 預備公開說明書公開後，搜尋「風險因素」章節，記下和 API 供應、定價、使用政策有關的段落。

本週脈絡
